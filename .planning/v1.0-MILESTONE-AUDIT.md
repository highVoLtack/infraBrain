### Integration Gaps (2)

**1. Executor halt → Resume state persistence (INTF-07)**
- `updateSessionForResume` (Phase 4) is exported and tested but never imported by executor (Phase 3) or execute route
- On circuit breaker / damage budget halt, `resumeMetadata` is never written to disk/SQLite
- `/infra:resume` queries for sessions with `resumeMetadata` — always finds none from real executions
- Resume route also uses a stub runner (always returns success with empty output)
- **Impact:** Resume flow works in isolation tests (mocked data) but cannot be triggered by real execution halts
- **Severity:** Tech debt — resume is a v1 feature that works structurally but is disconnected in the wiring

**2. Lock events not audited (SAFE-09)**
- `lock_acquired`, `lock_released`, `lock_conflict`, `lock_override` are defined in `AuditEventType`
- `summarizeAuditEntry` in formatter.ts has display logic for them
- Executor never calls `auditLogger.logExecution('lock_acquired', ...)` or `'lock_released'`
- **Impact:** Lock operations are silent in the audit trail
- **Severity:** Minor — locks work correctly, just not logged
