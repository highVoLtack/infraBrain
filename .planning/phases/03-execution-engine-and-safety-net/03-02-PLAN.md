  <name>Task 1: Lock types and lock manager with tests</name>
  <files>src/locks/types.ts, src/locks/manager.ts, tests/locks/manager.test.ts</files>
  <behavior>
    - acquireLock() creates .infrabrain/locks/{target}.lock file with JSON metadata when no lock exists
    - acquireLock() returns { status: 'locked', existing } when lock file already exists and is not stale
    - acquireLock() returns { status: 'stale', existing } when lock file exists but is older than staleTimeoutMs
    - acquireLock() uses writeFileSync with { flag: 'wx' } for atomic create (prevents race condition per research Pitfall 3)
    - releaseLock() removes the lock file for a given target
    - releaseLock() is a no-op (no error) if lock file does not exist
    - checkLock() returns null if no lock exists
    - checkLock() returns LockFile if lock exists
    - Lock file JSON contains: target, sessionId, adminName, createdAt (ISO string), pid (process.pid), planSummary
    - Lock conflict message includes session ID, admin name, and time since lock was acquired
    - promptLockOverride() returns true when admin types exact target name
    - promptLockOverride() returns false when admin types anything else or empty string
    - Locks directory is created if it doesn't exist
  </behavior>
  <action>
    Create `src/locks/types.ts`:
    - `LockFile` interface: { target: string; sessionId: string; adminName: string; createdAt: string; pid: number; planSummary: string }
    - `LockResult` type: { status: 'acquired' } | { status: 'locked'; existing: LockFile } | { status: 'stale'; existing: LockFile }
    - `LockStatus` type: LockFile | null

    Create `src/locks/manager.ts`:
    - `acquireLock(target: string, lockDir: string, meta: { sessionId: string; adminName: string; pid: number; planSummary: string }, staleTimeoutMs: number): LockResult`
      - Use `writeFileSync(lockPath, data, { flag: 'wx' })` for atomic create per research Pitfall 3.
      - On EEXIST, read existing lock, check staleness by comparing createdAt to Date.now() against staleTimeoutMs.
      - Return 'locked' or 'stale' accordingly.
      - Ensure `.infrabrain/locks/` directory exists (mkdirSync recursive).

    - `releaseLock(target: string, lockDir: string): void`
      - Remove lock file. Ignore ENOENT (idempotent).

    - `checkLock(target: string, lockDir: string): LockStatus`
      - Read and parse lock file. Return null if not found.

    - `formatLockConflict(lock: LockFile): string`
      - Format human-readable conflict message using chalk.yellow:
        "Target '{target}' is locked by session {sessionId} (started {timeAgo}). Admin: {adminName}"
      - Use relative time display (e.g., "15 minutes ago").

    - `promptLockOverride(lock: LockFile, rl: readline.Interface): Promise<boolean>`
      - Show lock conflict info via formatLockConflict.
      - Prompt: chalk.red(`Type '${lock.target}' to force-override or press Enter to cancel: `)
      - Return true only if answer === lock.target (exact match, same pattern as destructive approval).

    Create `tests/locks/manager.test.ts`:
    - Use temp directory (mkdtempSync) for lock files, clean up in afterEach.
    - Test acquire when no lock exists -> 'acquired', file created with correct JSON.
    - Test acquire when lock exists and not stale -> 'locked' with existing lock data.
    - Test acquire when lock exists and stale (create lock with old timestamp) -> 'stale'.
    - Test release removes file. Test release on nonexistent file is safe.
    - Test checkLock returns LockFile when exists, null when not.
    - Test formatLockConflict returns readable string with target, session, admin.
    - Test promptLockOverride with mock readline: correct input returns true, wrong input returns false.
    - Test atomic create: simulate race by pre-creating file before acquireLock -> returns 'locked'.
