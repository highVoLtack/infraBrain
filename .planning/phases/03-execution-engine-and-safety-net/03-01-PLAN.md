  <files>src/execution/runner.ts, src/execution/circuit-breaker.ts, src/execution/damage-budget.ts, tests/execution/runner.test.ts, tests/execution/circuit-breaker.test.ts, tests/execution/damage-budget.test.ts</files>
  <behavior>
    Runner:
    - parseCommand("docker inspect nginx") returns { executable: "docker", args: ["inspect", "nginx"] }
    - parseCommand('echo "hello world"') handles quoted strings (returns { executable: "echo", args: ["hello world"] })
    - parseCommand("ls -la /tmp") returns { executable: "ls", args: ["-la", "/tmp"] }
    - runCommand("echo", ["hello"], { timeout: 5000 }) returns { stdout: "hello\n", stderr: "", exitCode: 0 }
    - runCommand with nonexistent binary returns exitCode !== 0 with stderr
    - needsShell("cat file | grep pattern") returns true (pipe detected)
    - needsShell("docker inspect nginx") returns false

    Circuit Breaker:
    - execute() runs the function on first call
    - execute() retries on failure up to maxRetries times
    - execute() returns circuit_open after maxRetries failures
    - execute() calls budget.deductFailedRetry() on each failure
    - execute() resets failure count on success
    - Different step indices track independently

    Damage Budget:
    - costFor('read') returns 0
    - costFor('write') returns 1
    - costFor('destructive') returns 2
    - canAfford(1) returns true when budget has room
    - canAfford(1) returns false when budget is exhausted
    - deduct(2) reduces remaining by 2
    - deductFailedRetry('write') deducts 2 (double of costFor write)
    - deductFailedRetry('destructive') deducts 4 (double of costFor destructive)
    - remaining, total, spent getters work correctly
  </behavior>
  <action>
    Create `src/execution/runner.ts`:
    - `parseCommand(command: string)`: Split command string into { executable, args }. Handle single and double quoted strings. For complex commands (pipes, redirects), the caller should use shell mode instead.
    - `needsShell(command: string)`: Returns true if command contains |, >, >>, <, &&, ||, ;, or backtick. These require shell mode.
    - `runCommand(executable: string, args: string[], options: { timeout: number; maxBuffer?: number })`: Wraps `util.promisify(child_process.execFile)` with AbortController. Returns RunResult (always resolves, never throws -- extracts stdout/stderr from error on non-zero exit per Pitfall 2 from research).

    Create `src/execution/circuit-breaker.ts`:
    - `CircuitBreaker` class with constructor(maxRetries: number = 3, retryDelayMs: number = 1000).
    - `execute(stepIndex, fn, budget, risk)` method: runs fn, on failure increments counter and calls budget.deductFailedRetry(risk). If failures >= maxRetries, returns { status: 'circuit_open', result }. On success returns { status: 'success', result }. Between retries, wait retryDelayMs (use setTimeout promise). Check budget.canAfford before each retry -- if budget exceeded during retries, return circuit_open early.

    Create `src/execution/damage-budget.ts`:
    - `DamageBudget` class per research code example. Constructor takes limit (number).
    - `costFor(risk)`: read=0, write=1, destructive=2
    - `canAfford(cost)`: used + cost <= limit
    - `deduct(cost)`: used += cost
    - `deductFailedRetry(risk)`: used += costFor(risk) * 2 (SAFE-06)
    - Getters: remaining, total, spent

    Create test files with comprehensive coverage using vitest. Mock child_process.execFile in runner tests using vitest.mock. For circuit breaker tests, use a mock function that fails/succeeds as needed. Damage budget tests are pure unit tests.
