  <behavior>
    Executor:
    - executePlan iterates through FixPlan steps in order
    - Before starting: acquires lock on target, returns 'rejected' if lock conflict and no override
    - Each step: checks damage budget -> captures snapshot -> requests approval -> executes via circuit breaker -> updates context
    - On circuit_open: rolls back failing step, logs circuit_breaker_triggered, alerts admin, returns halted
    - On budget exceeded: rolls back failing step, logs damage_budget_exceeded, alerts admin, returns halted
    - On approval rejected: returns rejected at that step
    - On all steps complete: returns completed
    - After execution (success or halt): releases lock
    - Budget display after each step: "Budget: {spent}/{total} used" via chalk
    - Alert on safety trigger: bold red chalk warning with details

    Execute Route:
    - POST /execute accepts { sessionId, fixPlan, target, adminName }
    - Validates input
    - Calls executePlan with dependencies injected
    - Returns ExecutionResult as JSON
    - Logs execution_start and execution_complete audit events

    Debug Route Update:

  <action>
    Create `src/execution/executor.ts`:
    - `executePlan(plan: FixPlan, target: string, deps: ExecutionDeps): Promise<ExecutionResult>`
    - Pipeline per research Pattern 3:
      1. Acquire lock on target. If locked and not stale, call promptLockOverride. If stale, warn and prompt. If override refused, return rejected.
      2. Log execution_start.
      3. Create CircuitBreaker and DamageBudget from config.
      4. Create RollingContext with token budget from config.
      5. For each step:
         a. Check budget.canAfford(costFor(step.risk)). If not, rollback current step, log damage_budget_exceeded, alert admin with chalk.red.bold, return halted.
         b. If step.risk !== 'read': captureSnapshot.
         c. Request approval via deps (READ=auto, WRITE=Y/n, DESTRUCTIVE=typed). If rejected, return rejected.
         d. If needsShell(step.command): show shell mode warning via chalk.yellow, require additional HITL approval for shell execution.
         e. Execute via circuit breaker. If circuit_open: rollbackStep, log circuit_breaker_triggered, alert admin with chalk.red.bold("CIRCUIT BREAKER: Step {N} failed after {maxRetries} retries. Plan halted."), return halted.
         f. On success: deduct from budget. Log step_complete. Print budget status: chalk.dim(`Budget: ${budget.spent}/${budget.total} used`).
         g. Add result to rolling context.
      6. After loop: log execution_complete, release lock.
      7. Wrap entire executor in try/finally to ensure lock release even on unexpected errors.
