<objective>
Add TOON (Token-Oriented Object Notation) encoding for LLM context optimization.

Purpose: Reduce token consumption by ~40% when sending structured data (log entries, fix plan steps, infrastructure state) to the LLM. TOON uses YAML-like indentation + CSV-style tabular arrays to encode the JSON data model with fewer tokens while maintaining lossless round-trips.
Output: TOON encoder module, updated orchestrator context builder, updated execution rolling context. CLI --json and SQLite remain standard JSON.
</objective>

    - Test: encodeToon handles mixed structures (objects + arrays)
    - Test: encodeToon returns the input unchanged for primitive values (string, number, boolean, null)
    - Test: encodeForLLM wraps encodeToon with a label prefix ("Infrastructure State:\n{toon}")
    - Test: TOON encoding of a typical log entries array uses at least 20% fewer tokens than JSON.stringify
    - Test: TOON encoding of a fix plan steps array uses at least 20% fewer tokens than JSON.stringify
    - Test: TOON encoding is lossless — encoding then parsing back produces equivalent data
  </behavior>
  <action>
    1. Install the TOON package: `npm install @toon-format/toon`

    2. Create src/llm/toon-encoder.ts:
       - Import `encode` from `@toon-format/toon`
       - Import `estimateTokens` from `./token-budget.js`
       - `encodeToon(data: unknown): string` — wraps the TOON library's encode function. If encode throws (deeply nested non-uniform data), falls back to `JSON.stringify(data, null, 0)` (compact JSON as fallback)
       - `encodeForLLM(data: unknown, label?: string): string` — encodes data as TOON and prepends an optional label. Format: `{label}:\n{toonString}` or just `{toonString}` if no label
       - `measureSavings(data: unknown): { jsonTokens: number, toonTokens: number, savingsPercent: number }` — utility for testing/debugging that compares token counts between JSON.stringify and TOON encoding

    3. Write tests in tests/llm/toon-encoder.test.ts:
       - Test flat object encoding (e.g., `{ host: "nginx", status: "down", port: 80 }`)
       - Test uniform array encoding with realistic data:
         ```typescript
         const logEntries = [
           { timestamp: "2026-03-08T10:00:00Z", level: "error", source: "nginx", message: "502 Bad Gateway" },
           { timestamp: "2026-03-08T10:00:01Z", level: "error", source: "nginx", message: "upstream timeout" },
           { timestamp: "2026-03-08T10:00:02Z", level: "warn", source: "nginx", message: "retry limit reached" },
         ];
         ```
       - Test fix plan steps encoding:
         ```typescript
         const steps = [
           { command: "docker inspect nginx", description: "Check container state", rollback: "", risk: "read" },
           { command: "docker restart nginx", description: "Restart the container", rollback: "docker stop nginx", risk: "write" },
         ];
         ```
       - Test token savings: assert `measureSavings(logEntries).savingsPercent > 20`
       - Test token savings: assert `measureSavings(steps).savingsPercent > 20`
       - Test lossless round-trip (if TOON library exposes decode/parse)
       - Test graceful fallback: pass deeply nested non-uniform data, verify it returns compact JSON instead of throwing
       - Test encodeForLLM with label produces correct format

    All imports use .js extensions per project ESM convention.
