    - Passing any non-step event type to it continues to work exactly as before.

  <files>src/audit/logger.ts, src/execution/types.ts, tests/audit/logger.test.ts</files>

  <action>
    Narrow the general-purpose execution logger's event-type parameter from the full audit event
    union to that union with the step-family types excluded, using TypeScript's `Exclude` utility
    type.

    Apply the identical narrowing in three places so no door is left open:
    - `AuditLogger.logExecution` in `src/audit/logger.ts`.
    - The `logExecution` member of the `ExecutionDeps.auditLogger` structural shape.
    - The `logExecution` member of the `SelfHealContext.auditLogger` structural shape.

    Narrowing only the class while leaving the structural shapes wide would leave the executor and
    the self-healer — the two files that had the defect — free to emit a step event through the
    untyped door. The structural shapes are the contract those files actually see.

    This narrowing is what turns the D-2 invariant from a nudge into a guarantee. With it there is no
    compiling path to a step event that lacks an attempt number. Without it, `logStepEvent` is merely
    the polite option.

    Run `npx tsc --noEmit` and confirm the narrowing produces no new errors. If it does, a
    step-family emission still exists somewhere — find it and migrate it to the typed door rather
    than widening the type back or casting.

    Add a compile-time assertion to `tests/audit/logger.test.ts`: a `@ts-expect-error` fixture whose
    body passes a step-family event type to the general-purpose logger. The `@ts-expect-error`
    directive itself becomes a compile error if the call ever stops being rejected, which means the
    guarantee is checked by the type-checker on every run rather than by anyone remembering to look.
    Add a comment above it explaining that inversion, because a `@ts-expect-error` with no
    explanation reads like a bug to the next contributor.

    Also assert at runtime that the typed door still accepts all three step-family types.
  </action>

  <verify>
    <automated>npx tsc --noEmit 2>&amp;1 | grep -cE "src/(audit/logger|execution/types)\.ts" | grep -qx 0 &amp;&amp; npx vitest run tests/audit/logger.test.ts</automated>
  </verify>
