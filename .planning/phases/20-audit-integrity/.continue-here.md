<decisions_made>

**Locked owner decisions for phase 20** (full text in `20-CONTEXT.md` — do not relitigate):

- **D-1** — historical records are never rewritten, migrated, or backfilled. They are evidence of the
  past, including the flawed past. A record without `attempt_n` is a legitimate pre-fix state.
- **D-2** — append-only from the fix onward; `attempt_n` on every step event with **no exceptions**,
  attempt 1 included. It is the *sole* discriminant between the two schema eras D-1 keeps alive, so one
  event without it collapses the distinction. Test the **emitter**, not sample payloads.
- **D-3** — status derived exclusively from events. Exactly one terminal event per
  `(stepIndex, attempt_n)`; zero = in-flight if the session is open, violation if closed; two or more =
  always a violation. Violations **surface**; they are never resolved into a plausible outcome.
- **D-4** — the regression test's RED state must be an artifact (RED commit or persisted output).
- **D-5** — `src/api/routes/history.ts` is **in** scope; `src/ui/App.tsx` and `src/cli/formatter.ts`
  stay hard-frozen. If either frozen file needs a change, the payload contract was misread — surface
  that, do not accommodate it.

**Forced by code, not preference:**
- `attempt_n` must live in `metadata`. `appendAudit` (`src/state/store.ts:185-209`) writes the whole
  entry to JSONL but INSERTs a **fixed column list**; a top-level field would be silently dropped on
  the exact path replay reads (SQLite via `/history`).
- `self_heal_attempt` and step events **coexist**. Settled empirically: `self_heal_attempt` carries no
  `stepIndex` in any of the 98 historical records, so it never was an attributable outcome record. Step
  events become canonical and the sole input to status derivation; `self_heal_attempt` stays
  LLM-correction rationale and gains `stepIndex` + `attempt_n` as a join key. Anti-duplication is a
  **precedence rule made mechanical** — a test where `self_heal_attempt.outcome: 'success'` contradicts
  `step_failed` must derive **failed**.

**Deliberately not done:**
- `session_end` emission. Would close a 1.8% `indeterminate` gap in one line, but sits outside
  "producer side, step events" and the feature freeze admits no silent exceptions. Plan-checker
  confirmed criterion 6 is not endangered — 20-05 introduces `indeterminate` as an honest fourth state,
  which is needed regardless since crashed sessions lack a terminal marker even with `session_end`.

**Two planner deviations from research, both verified sound:**
- `executor.ts:374-392` builds `healContext` **once**, before the loop at line 400, while each
  iteration references `rev.configMod.stepIndex` — a *different* step. Research's fixed `stepIndex` +
  `let attemptN = 1` would have mis-attributed persistence-fix attempts, silently (the frozen consumer
  discards non-numeric indices but files merely-wrong ones happily). Planner used a per-iteration
  spread plus a `Map<number, number>` counter.
- Circuit-breaker callback split into two argument-light callbacks instead of research's single
  `onAttempt(attemptNumber, result)` — an attempt's *start* has no result, and giving the breaker a
  notion of global attempt number reintroduces the off-by-one class. Executor owns all numbering.

**Project-level, from this session:**
- Sequencing is by **dependency, not calendar** — no week numbers. Governing chain: loop proof gates
  the demo, demo gates the funnel.
- Gemini is a deliberate development stand-in, not architecture drift (RunPod costs money and adds
  spin-up latency). Rule: build against Gemini, behave as if local. Consequence in dossier section G —
  structural fixes transfer to the local backend, **numeric tuning does not**, so never tune
  latency/retry constants against Gemini.
- Phase 17.1 stays frozen.
