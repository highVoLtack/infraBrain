<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| command execution -> audit record | The only moment an attempt's outcome can be captured; nothing downstream can recover it |
| retry loop internals -> executor | Attempts happen inside the breaker, invisible to the caller by default |
| step event payload -> replay consumer | The consumer is frozen, so any contract error must be fixed producer-side |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-20-19 | Repudiation | failing attempt leaves no record | critical | mitigate | Failure events at both attempt-1 sites plus a breaker failure callback that fires before the early returns; asserted as attempt numbers `[1,2,3,4]` in the exhaustion test |
| T-20-20 | Repudiation | duplicate terminal event at the halt sites | high | mitigate | The two halt markers are left untouched by explicit instruction; the last failing attempt already emitted its own terminal event, and a second would violate the cardinality invariant plan 20-05 enforces |
| T-20-21 | Repudiation | causally inverted trail (rollback before failure) | medium | mitigate | Failure events are emitted inside the retry paths, strictly before the rollback calls at lines 242 and 304; pinned by an ordering assertion |
| T-20-22 | Tampering | persistence-fix attempts attributed to the wrong step | medium | mitigate | Per-iteration context override with the reverted step's own index and attempt count; a Map-based counter rather than a loop-local variable makes the correct value available |
| T-20-23 | Information disclosure | `stdout`/`stderr` in the audit record | medium | accept | Capturing command output is the explicit purpose of criterion 4; records are written under `.infrabrain/`, which is gitignored |
| T-20-24 | Denial of service | audit emission altering damage-budget halt timing | medium | mitigate | Emission is explicitly side-effect free; the uncharged attempt-1 failure is left uncorrected and noted for the dossier rather than changed here |
</threat_model>
