  <action>
    In `src/execution/types.ts`, make three additive changes.

    First, add `logStepEvent` to the `ExecutionDeps.auditLogger` structural shape (lines 42-44) as a
    REQUIRED member with the signature
    `(eventType: StepEventType, payload: StepEventPayload) => void`.
    Import both types from `../audit/types.js`. The file already imports `AuditEventType` from that
    module at line 3, so extend that import rather than adding a second one.

    Second, make the identical addition to the `SelfHealContext.auditLogger` structural shape
    (lines 95-97). Note this one currently uses inline `import(...)` type syntax; keep the file's
    existing style consistent, but the resulting member must be required and identically typed.

    Third, extend `SelfHealContext` with the step identity the self-healer needs in order to emit a
    step event that can be attributed to a step at all:
    - `stepIndex: number` — which plan step this heal loop is repairing.
    - `totalSteps: number` — the plan's step count, required by the replay payload contract.
    - `target: string` — the execution target, required by the replay payload contract.
    - `attemptBase: number` — how many attempts have ALREADY been made at this step before the heal
      loop begins.

    All four are REQUIRED. Making them optional would let the second `healContext` construction site
    in the executor silently omit them, which produces step events with an undefined `stepIndex` —
    and `buildReplayState` DISCARDS those without an error. The symptom of that mistake is nothing
    at all, which is why the type must forbid it.

    Document `attemptBase` with a comment stating precisely what it means and why it exists: the
    self-healer computes each attempt's global number as `attemptBase + attempts.length + 1`, and
    it exists because the self-healer's own pre-existing `attempt` field counts only heal-loop
    iterations and therefore denotes a different number. Reusing that pre-existing counter as the
    global attempt number would off-by-one the entire new schema, since the executor's own first
    execution is not among the heal loop's iterations.

    Do NOT rename or remove `self_heal_attempt`'s existing `attempt` field anywhere. The two numbers
    are different quantities and both stay.

    This task will produce compile errors in `src/execution/executor.ts` (the two `SelfHealContext`
    literals now missing four required fields). That is expected and correct — those sites are fixed
    in plan 20-06. Note the error count in your SUMMARY; do not fix the executor here, and do not
    weaken the types to make the errors disappear.
  </action>
