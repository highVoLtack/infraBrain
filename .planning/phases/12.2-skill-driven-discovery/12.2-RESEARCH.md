**Researched:** 2026-03-14

## Summary

Phase 12.2 moves the hardcoded `DISCOVERY_COMMANDS` constant from `src/api/routes/debug.ts` into skill YAML frontmatter. This is a straightforward migration following the exact pattern established by Phase 12.1 (which moved rewrite rules into skill frontmatter). The constant contains 4 entries (nginx-troubleshoot, postgres-troubleshoot, docker-storage, linux-filesystem-troubleshoot) with a total of 16 discovery commands. The `runDiscovery` function currently takes a `skillName: string` and looks up commands from the constant -- it needs to take a `SkillFile` and read from `skill.frontmatter.discovery`.

The main technical risk is YAML quoting for Docker format strings containing `{{.Names}}` and similar Go template syntax. These double braces conflict with some YAML parsers but `gray-matter` (the project's frontmatter parser) uses `js-yaml` which handles them correctly inside quoted strings. The project already uses single-quoted YAML strings for regex patterns in `rewrite_rules` -- the same approach works for discovery commands.

**Primary recommendation:** Follow the Phase 12.1 pattern exactly -- add `discovery` field to `SkillFrontmatterSchema`, migrate commands to skill YAML, refactor `runDiscovery` to take `SkillFile`, delete the constant.

## YAML Quoting Strategy

### The Problem

Discovery commands contain Go template syntax: `{{.Names}}`, `{{.Status}}`, `{{range .Containers}}...{{end}}`. These double braces can interfere with YAML parsing.

### The Solution

Use YAML single-quoted strings, exactly as the project already does for regex patterns in `rewrite_rules`. The `gray-matter` library uses `js-yaml` which handles `{{...}}` inside single-quoted strings without issue.

```yaml
discovery:
  - command: 'docker ps --format "{{.Names}}"'
    label: 'Running containers'
```

### Verified: Existing Skill Pattern

From `postgres-troubleshoot.md` rewrite_rules:
```yaml
rewrite_rules:
  - match: '^(SELECT|SHOW|INSERT|UPDATE|DELETE|WITH|EXPLAIN)\b'
    container: auto
    wrapper: 'psql -U postgres -c "{cmd}"'
```

Single-quoted strings with special characters already work. The discovery commands follow the same pattern.

### Edge Case: Embedded Single Quotes

The postgres-troubleshoot discovery has one command with embedded single quotes:

```
docker exec postgres-demo psql -U postgres -t -A -c "SELECT pid, state, client_addr, usename, query, state_change FROM pg_stat_activity WHERE state = 'idle' ORDER BY state_change"
```

In YAML single-quoted strings, single quotes are escaped by doubling: `''`. So this becomes:

```yaml
- command: 'docker exec postgres-demo psql -U postgres -t -A -c "SELECT pid, state, client_addr, usename, query, state_change FROM pg_stat_activity WHERE state = ''idle'' ORDER BY state_change"'
  label: 'Idle connections detail'
```

This is the ONE tricky command. All other commands use double quotes only and work cleanly in YAML single-quoted strings.

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| YAML parsing | Custom frontmatter parser | `gray-matter` + `js-yaml` (already used) | Handles edge cases, quoting, types |
| Schema validation | Manual type checking | Zod `.default([])` pattern (already established) | Automatic defaults, error messages, type inference |
| Discovery fallback | Explicit checks for missing field | `.default([])` in Zod schema | Empty array means the `for` loop just doesn't execute |

## Common Pitfalls

### Pitfall 1: YAML Double-Brace Parsing

**What goes wrong:** `{{.Names}}` in unquoted YAML strings can be interpreted as flow mappings or cause parse errors.
**Why it happens:** YAML spec uses `{` and `}` for flow mappings.
**How to avoid:** Always single-quote discovery command strings. Test parsing with `gray-matter` before committing.
**Warning signs:** Skill loading errors mentioning unexpected characters.

### Pitfall 2: Single Quotes Inside Single-Quoted YAML

**What goes wrong:** The postgres idle connections command contains `state = 'idle'` with embedded single quotes.
**Why it happens:** YAML single-quoted strings use `''` (doubled) to escape a literal single quote.
**How to avoid:** Use `''idle''` in the YAML. Verify the parsed command string matches the original exactly.
**Warning signs:** Truncated command strings, parse errors, or `state = idle` without quotes.

### Pitfall 3: E2E Test Breakage from Discovery Changes

**What goes wrong:** E2E tests fail because discovery commands no longer work.
**Why it happens:** Tests run real Docker commands -- if the commands change, they break.
**How to avoid:** E2E tests do NOT mock `DISCOVERY_COMMANDS`. They mock `selectSkill` and `generateFixPlan` at the orchestrator level, then run real discovery commands against Docker. Since we are moving the SAME commands into YAML (not changing them), E2E tests will continue to work AS LONG AS the parsed YAML produces identical command strings.
**Warning signs:** Verify parsed commands match originals character-for-character.

### Pitfall 4: Import Cycle from SkillFile Type

**What goes wrong:** Importing `SkillFile` in debug.ts creates a circular dependency.
**Why it happens:** debug.ts already imports from skills/registry, which imports from skills/types.
**How to avoid:** `SkillFile` is already available via `skills/types.ts`. debug.ts already uses `SkillFile` objects from `selectSkill()`. No new import needed -- just change the function signature.

### Pitfall 5: DEV_MODE Logging Changes

**What goes wrong:** Discovery DEV_MODE logging references `skillName` for context.
**Why it happens:** After refactor, `runDiscovery` receives a `SkillFile` not a name.
**How to avoid:** Use `skill.frontmatter.name` in the logging line. Currently the function does NOT log the skill name (only TOON savings), so this is a non-issue.

## Open Questions

1. **Embedded single quotes in YAML**
   - What we know: The postgres idle connections command has `state = 'idle'` with single quotes. YAML single-quoted strings escape single quotes by doubling (`''`).
   - What's unclear: Whether `gray-matter`/`js-yaml` correctly round-trips `''idle''` back to `'idle'` in the parsed string.
   - Recommendation: Write a unit test that loads the postgres skill and verifies the parsed command matches the original character-for-character. If doubling doesn't work, use YAML block scalar (`|`) or double-quoted string with escaped quotes instead.

2. **runDiscovery export status**
   - What we know: `runDiscovery` is currently a private module-level function in debug.ts, not exported.
   - What's unclear: Whether to extract it to a separate file for testability.
   - Recommendation: Keep it in debug.ts but export it for unit testing. Alternatively, test via the E2E path. The function is only 20 lines.
