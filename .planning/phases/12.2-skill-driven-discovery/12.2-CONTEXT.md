# Phase 12.2: Skill-Driven Discovery - Context

**Gathered:** 2026-03-14
**Status:** Ready for planning
**Source:** User specification via /gsd:insert-phase

<domain>
## Phase Boundary

This phase completes the Agnostic Engine transition. After Phase 12.1 moved command rewriting into skill frontmatter, the last hardcoded domain knowledge in debug.ts is the `DISCOVERY_COMMANDS` constant. This phase moves discovery commands into skill YAML, making the engine a pure execution pipe with 100% domain knowledge in Markdown files.

</domain>

<decisions>
## Implementation Decisions

### Schema Extension
- Add `discovery` field to `SkillFrontmatterSchema` in `src/skills/types.ts`
- Type: array of `{ command: string, label: string }`, optional, defaults to `[]`
- Zod schema with validation (command non-empty, label non-empty)

### Orchestrator Refactor
- Refactor `runDiscovery` in `src/api/routes/debug.ts` to take the `SkillFile` as argument
- Read discovery commands from `skill.frontmatter.discovery` instead of `DISCOVERY_COMMANDS[skillName]`
- Remove the `DISCOVERY_COMMANDS` constant entirely

### Skill Migration
- Move discovery commands from debug.ts into YAML frontmatter of each skill:
  - `skills/nginx-diagnose.md` (or nginx-troubleshoot.md — check actual name)
  - `skills/postgres-troubleshoot.md`
  - `skills/docker-storage.md`
  - `skills/linux-filesystem-troubleshoot.md`

### Graceful Fallback
- If a skill has no `discovery` section (empty array or undefined), orchestrator skips discovery phase
- No error, no warning — simply proceed without ground truth injection
- This enables "lightweight" skills that don't need environment scanning

### Claude's Discretion
- Whether to also extract the `nginx-troubleshoot` discovery commands (check if they exist)
- Exact shape of the Zod schema for discovery entries
- How to handle the planning/verification skills that don't have discovery
- Test strategy for the migration

</decisions>

<specifics>
## Specific Ideas

- The discovery array in YAML should look like the existing DISCOVERY_COMMANDS entries:
  ```yaml
  discovery:
    - command: 'docker ps -a --format "{{.Names}} {{.Status}}"'
      label: 'All containers with status'
    - command: 'docker logs permission-app --tail 50'
      label: 'App crash logs'
  ```
- debug.ts should shrink by ~100 lines after removing the constant
- The `runDiscovery` function signature changes from `(skillName: string)` to `(skill: SkillFile)` or similar
- E2E tests that mock discovery should still work — they mock at the execution level, not the constant level

</specifics>
