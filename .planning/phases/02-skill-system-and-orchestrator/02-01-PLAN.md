    2. Extend src/config/types.ts: Add `skillsDir: z.string().default('skills')` to InfraBrainConfigSchema.

    3. Create src/skills/types.ts with:
       - SkillFrontmatterSchema (Zod): name (string, min 1), description (string, min 10), triggers (string array, min 1), tools (string array, default []), version (string, optional), author (string, optional), priority (number, default 0)
       - SkillSectionsSchema (Zod): systemPrompt (string, min 1), tools (string, optional), examples (string, optional)
       - Type exports via z.infer: SkillFrontmatter, SkillSections
       - SkillFile interface: { frontmatter: SkillFrontmatter, sections: SkillSections, rawContent: string, filePath: string }

    4. Create src/skills/format.ts:
       - parseSections(content: string): Record<string, string> -- splits Markdown body on ## headings, normalizes keys to snake_case (e.g., "System Prompt" -> "system_prompt"). Use regex /^## (.+)$/gm as shown in research.

    5. Create src/skills/loader.ts:
       - loadSkillFile(filePath: string): SkillFile -- uses gray-matter to parse frontmatter, validates with SkillFrontmatterSchema.parse(), calls parseSections on content, validates systemPrompt exists. Throws with clear error: `Skill "${filePath}": {specific issue}`.
       - loadSkillDirectory(dirPath: string): { skills: SkillFile[], errors: Array<{ file: string, error: string }> } -- reads all .md files from directory, calls loadSkillFile for each, catches errors per-file, returns both loaded and failed.

    6. Create src/skills/registry.ts:
       - SkillRegistry class with private Map<string, SkillFile>
       - populate(dirPath: string): void -- calls loadSkillDirectory, stores in map by name, logs errors
       - get(name: string): SkillFile | undefined
       - list(): Array<{ name: string, description: string }> -- returns summaries for routing
       - getAll(): SkillFile[] -- returns all loaded skills

    7. Create src/skills/allowlist.ts:
       - enforceSkillAllowlist(command: string, skill: SkillFile): { allowed: boolean, reason?: string }
       - If skill.frontmatter.tools is empty, return allowed: true (no restriction)
       - Split command on shell operators (;, &&, ||, |) and check each sub-command's base command (first word) against skill.frontmatter.tools
       - If any sub-command fails, return allowed: false with reason naming the disallowed command

    8. Create test fixtures: tests/fixtures/skills/valid-skill.md (valid with all sections), malformed-no-name.md (missing name), malformed-no-prompt.md (has frontmatter but no ## System Prompt).

    9. Write tests in tests/skills/loader.test.ts covering all behaviors listed above. Use actual fixture files, not mocks. Use temp directories (mkdtempSync) for registry tests.

    All imports use .js extensions per project ESM convention.
