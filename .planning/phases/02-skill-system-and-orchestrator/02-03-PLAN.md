  <action>
    1. Create src/orchestrator/types.ts:
       - FixStepSchema (Zod): command (string), description (string), rollback (string), risk (enum: read/write/destructive)
       - FixPlanSchema (Zod): summary (string), steps (array of FixStepSchema), complexity (enum: simple/moderate/complex)
       - SkillSelectionSchema (Zod): selectedSkill (string), reasoning (string)
       - Type exports: FixStep, FixPlan, SkillSelection via z.infer
       - OrchestratorResult interface: { skill: SkillFile, diagnosis: string, plan?: FixPlan, planMarkdown?: string }

    2. Create src/orchestrator/context.ts:
       - buildMessages(skill: SkillFile, userInput: string): { system: string, messages: Array<{role, content}> }
         Per user decision: system prompt as system message, skill context (tools + examples) as assistant message, user input as user message.
       - buildRoutingPrompt(skills: Array<{name, description}>, userInput: string): string
         Format: "User query: {input}\n\nAvailable skills:\n- name: description\n..."

    3. Create src/orchestrator/router.ts:
       - selectSkill(options: { model: LanguageModel, userInput: string, registry: SkillRegistry, skillOverride?: string }): Promise<{ skill: SkillFile, reasoning: string }>
       - If skillOverride provided: look up in registry, throw if not found, return directly with reasoning "Manual override"
       - Otherwise: call generateObject with SkillSelectionSchema, passing buildRoutingPrompt output
       - System prompt: "You are a skill router. Given a user query and available skills, select the most appropriate skill."
       - Return matched skill from registry + reasoning

    4. Create src/orchestrator/planner.ts:
       - generateFixPlan(options: { model: LanguageModel, skill: SkillFile, userInput: string, diagnosis: string }): Promise<FixPlan>
       - Uses buildMessages with the planning skill, appends the diagnosis context
       - Calls generateObject with FixPlanSchema
       - generatePlanMarkdown(plan: FixPlan): string -- Markdown table per research example
       - formatPlanTable(plan: FixPlan): string -- CLI table using chalk: "# | Command | Risk | Status" with risk-level color coding (read=green, write=yellow, destructive=red). Status starts as "pending" for all steps.

    5. Write tests:
       - tests/orchestrator/router.test.ts: Mock generateObject via vi.mock('ai'). Test selectSkill with LLM routing (mock returns valid selection). Test --skill override (no LLM call). Test invalid override throws.
       - tests/orchestrator/planner.test.ts: Mock generateObject. Test generateFixPlan returns typed FixPlan. Test generatePlanMarkdown output format. Test formatPlanTable output format.

    Mock the AI SDK generateObject in tests -- do NOT call a real LLM. Use vi.mock('ai', () => ({ generateObject: vi.fn() })) pattern.

    All imports use .js extensions per project ESM convention.
