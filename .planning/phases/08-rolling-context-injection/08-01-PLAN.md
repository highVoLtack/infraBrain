1. In `src/execution/types.ts`, add an optional `onBeforeStep` callback to `ExecutionDeps`:
   ```typescript
   onBeforeStep?: (stepIndex: number, rollingContext: string) => Promise<void>;
   ```
   This callback receives the step index about to execute and the accumulated rolling context string from all prior completed steps. It is async to allow LLM calls.

2. In `src/execution/executor.ts`, in the step loop (line ~94), AFTER the skip check and BEFORE the budget check, add:
   ```typescript
   // Inject rolling context for steps after step 0
   const currentContext = context.getContext();
   if (deps.onBeforeStep && currentContext && i > 0 && !skipThisStep) {
     await deps.onBeforeStep(i, currentContext);
   }
   ```
   Place this injection point right after the `if (skipThisStep)` block and before the `const cost = budget.costFor(step.risk)` line. The `currentContext` check ensures we don't call with empty string. The `i > 0` check ensures step 0 never triggers (no prior context). The `!skipThisStep` is redundant with the earlier continue but defensive.

   NOTE: The rolling context at this point contains results from steps 0..i-1 because `context.addStepResult` is called at the END of each step (line ~220). So by the time we reach step i, all prior completed steps are in the context.

3. Create `tests/execution/rolling-context-injection.test.ts` with the test behaviors listed above. Use the same mock pattern as `tests/execution/executor.test.ts` (mock locks, snapshot, rollback, chalk). Use `vi.fn()` for onBeforeStep and assert call count, call arguments, and context content.

   Key test fixture: a 3-step read plan where the runner returns different stdout for each step ("step-0-output", "step-1-output", "step-2-output") so we can assert the context content precisely.
