  <action>
Create `tests/e2e/` directory and `poc-nginx-502.test.ts`. This test mocks the LLM but runs real Docker commands against the demo environment.

**Test setup (beforeAll):**
- Run `demo/reset.sh` via execSync with 30s timeout and cwd set to project root
- Verify broken state: `curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/get` returns "502"
- Create temp directory for session storage (mkdtempSync)
- Initialize WriteThrough store with SQLite in temp dir
- Create a mock LLM provider that:
  - `generateCommand()` returns a canned diagnosis string mentioning network isolation, upstream connection refused, and the `docker network connect` fix
  - `model` returns a mock LanguageModel object (for generateObject calls)
- Create mock for `generateObject` (from ai library) that returns a canned FixPlan with:
  - summary: "Connect backend container to frontend network"
  - steps: [
      { command: "docker network connect demo_frontend demo-backend", risk: "write", rollback: "docker network disconnect demo_frontend demo-backend", expected: "Backend joined to frontend network" },
      { command: "curl -s -o /dev/null -w \"%{http_code}\" http://localhost:8080/get", risk: "read", rollback: "N/A", expected: "HTTP 200" }
    ]
- Mock `selectSkill` to return the nginx-troubleshoot skill (load it from skills/nginx-troubleshoot.md using the real skill loader)
- Mock `generateFixPlan` to return the canned FixPlan above (since it calls generateObject internally which would need a real LLM)
- Create SkillRegistry populated with real skills from skills/ directory
- Create AuditLogger with the WriteThrough store
- Build ServerDeps with all required fields (provider, auditLogger, validator using real classifyCommand+validateCommand, ollamaBaseUrl, registry, config with defaults, sessionId from uuid, sessionDir in temp, store, lockDir in temp)
- Create Express app via `createServer(deps).app`

**CRITICAL mocking strategy:** The simplest approach is to mock at module level:
- Mock `../../src/orchestrator/router.js` so `selectSkill` returns the nginx-troubleshoot skill with canned reasoning
- Mock `../../src/orchestrator/planner.js` so `generateFixPlan` returns the canned FixPlan, but keep `generatePlanMarkdown` and `formatPlanTable` as real implementations
- Mock `../../src/llm/provider.js` or the provider's `generateCommand` to return canned diagnosis text
- Use `vi.mock()` for module-level mocks

**Test teardown (afterAll):**
- Run `docker compose -f demo/docker-compose.yml down --remove-orphans` with 15s timeout
- Clean up temp directory

**Test cases:**

1. `it('broken environment returns 502')` (POC-01):
   - curl localhost:8080/get via execSync
   - Expect HTTP 502

2. `it('diagnoses broken Nginx and generates fix plan')` (POC-02):
   - POST /debug with `{ prompt: "Why is Nginx returning 502?" }`
   - Expect 200 response
   - Expect `res.body.diagnosis` to be defined (canned diagnosis)
   - Expect `res.body.fixPlan` to be defined with steps
   - Expect `res.body.fixPlan.steps.length` >= 1
   - Expect `res.body.skillMessage` to contain "nginx-troubleshoot"
   - Store sessionId and fixPlan for next test

3. `it('executes fix plan and verifies health')` (POC-02):
   - POST /execute with `{ sessionId, fixPlan, target: "nginx", adminName: "e2e-test" }`
   - Expect 200 response
   - Expect `res.body.status` to be "completed"
   - Verify fix via execSync: `curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/get` returns "200"

4. `it('audit trail contains full DPEV evidence')` (POC-03):
   - GET /history with `{ session: sessionId }` (or query the store directly via `store.queryAuditLog`)
   - Expect entries to exist
   - Expect event types to include: `skill_selection`, `decision`, `execution_start`, `step_complete`, `execution_complete`
   - Verify at least one entry contains reasoning/diagnostic information

**Important implementation notes:**
- Use `describe('POC: Nginx 502 End-to-End', ...)` as top-level describe
- Set vitest timeout to 60000ms for the describe block (Docker operations are slow)
- The tests must run SEQUENTIALLY within the describe block since test 3 depends on test 2's output and test 4 depends on test 3's side effects. Use variables in describe scope to pass sessionId/fixPlan between tests.
- Docker container names use the project name prefix. Since docker-compose.yml is in `demo/`, the project name defaults to "demo". Network names will be `demo_frontend` and `demo_backend`. Container names should use explicit `container_name` from Plan 01.
- The execute route auto-approves all commands (requestApproval always returns true), so no readline mock needed
- Import paths must use `.js` extensions per project ESM convention
