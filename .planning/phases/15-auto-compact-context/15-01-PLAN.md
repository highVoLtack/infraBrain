<task type="auto" tdd="true">
  <name>Task 2: Noise filter with regex patterns and worker model fallback</name>
  <files>src/context/noise-filter.ts, src/skills/types.ts, tests/context/noise-filter.test.ts</files>
  <behavior>
    - filterNoise removes lines matching healthcheck spam patterns (e.g., "health_status: healthy")
    - filterNoise removes lines matching systemd boilerplate (e.g., "Started foo.service", "systemd[1]: Starting")
    - filterNoise removes journal metadata lines ("-- Logs begin at", "-- No entries --")
    - filterNoise removes empty/whitespace-only lines
    - filterNoise applies skill-declared noise_patterns from string[] (compiled to RegExp)
    - filterNoise does NOT invoke worker model when unrecognized lines < 10
    - filterNoise invokes worker model when unrecognized lines >= 10, passing them as a batch
    - filterNoise returns { filtered: Record<string, string>, removedCount: number, workerModelUsed: boolean }
  </behavior>
  <action>
    1. Add `noise_patterns: z.array(z.string()).default([])` to `SkillFrontmatterSchema` in `src/skills/types.ts`.
    2. Create `src/context/noise-filter.ts`:
       - Export `NOISE_PATTERNS: RegExp[]` array with hardcoded patterns per RESEARCH.md:
         - Docker healthcheck: `/health_status:\s*(healthy|unhealthy)/i`, `/healthcheck.*passed|healthcheck.*failed/i`
         - systemd: `/Started\s+.*\.service/`, `/Stopped\s+.*\.service/`, `/systemd\[\d+\]:\s+Starting\s+/`, `/systemd\[\d+\]:\s+Reached target\s+/`
         - Journal: `/-- Logs begin at/`, `/-- No entries --/`, `/-- Journal has been rotated/`
         - Whitespace: `/^\s*$/`
       - Export `filterNoise(discoveryRaw: Record<string, string>, skillPatterns?: string[], workerModel?: LanguageModel): Promise<{ filtered: Record<string, string>, removedCount: number, workerModelUsed: boolean }>`
         - Compile skillPatterns strings to RegExp at call time
         - For each key in discoveryRaw, split value by newlines
         - Test each line against NOISE_PATTERNS + compiled skill patterns
         - Lines matching any pattern are removed
         - Lines NOT matching any pattern are "unrecognized" -- if a single discovery key has 10+ unrecognized lines AND workerModel is provided, batch them and call the worker model using `generateObject` from `ai` SDK with a schema `{ relevant: z.array(z.string()) }` asking which lines are relevant to infrastructure diagnosis
         - If workerModel not provided or <10 unrecognized lines, include all unrecognized lines
         - Reassemble filtered lines per key
    3. Write tests in `tests/context/noise-filter.test.ts`:
       - Mock the `ai` SDK `generateObject` for worker model tests
       - Test each noise pattern category
       - Test skill-declared patterns
       - Test 10-line threshold (9 lines = no worker call, 10 lines = worker call)
       - Test without workerModel provided (all unrecognized lines included)
  </action>
  <verify>
    <automated>npx vitest run tests/context/noise-filter.test.ts</automated>
  </verify>
  <done>Noise filter removes all hardcoded noise patterns, applies skill patterns, invokes worker model only at 10+ unrecognized lines threshold, all tests pass</done>
</task>
