       ```
       contextWindow: z.number().default(32768),
       ```
       This is the model's full context window size. The 83% threshold and 60% target are percentages of this.

    2. In `src/llm/token-budget.ts`:
       - Add import: `import { countTokens as countTokensAccurate } from '../context/token-counter.js';`
       - Add new export: `export { countTokensAccurate as countTokens } from '../context/token-counter.js';`
       - Keep `estimateTokens` as-is (backward compat fallback) but add a JSDoc note: "Heuristic fallback. Prefer countTokens from context/token-counter for accurate BPE counting."
       - Update `checkBudget` to use `countTokensAccurate` instead of `estimateTokens` for the primary check.

    3. In `src/orchestrator/pipeline.ts`, modify `runDPEV()`:
       - Add imports: `import { ContextManager } from '../context/context-manager.js';`, `import { filterNoise } from '../context/noise-filter.js';`
       - After `runParallelDiscovery()` returns and before diagnosis:
         a. Get worker model: `const workerModel = provider.registry?.get?.('worker');`
         b. Get skill noise patterns: `const skillNoisePatterns = selection.skill.frontmatter.noise_patterns ?? [];`
         c. Run noise filter: `const { filtered: filteredRaw, removedCount, workerModelUsed } = await filterNoise(discoveryRaw, skillNoisePatterns, workerModel);`
         d. Log in DEV_MODE: `[NOISE] Filtered {removedCount} noise lines` and if workerModelUsed: `[NOISE] Worker model used for relevance scoring`
         e. Instantiate ContextManager: `const contextManager = new ContextManager({ windowSize: input.config?.contextWindow ?? 32768, threshold: 0.83, target: 0.60, groundTruthCap: 0.20 }, input.config?.sessionDir, input.sessionId);`
         f. Ingest: `contextManager.ingestDiscovery(filteredRaw);`
         g. Log usage: `if (DEV_MODE) console.log(\`[CONTEXT] ${contextManager.getUsage().percentage.toFixed(1)}% used (${contextManager.getUsage().tokens} tokens)\`);`
         h. Check compaction: `const compactionResult = await contextManager.maybeCompact(workerModel);` and log if fired
         i. Build enriched prompt using contextManager: Replace the existing ad-hoc `--- GROUND TRUTH ---` block with `contextManager.buildContext()`. The new enrichedPrompt becomes:
            ```
            const contextBlock = contextManager.buildContext();
            const enrichedPrompt = contextBlock
              ? `${prompt}\n\n${contextBlock}\n\nMANDATORY: Use ONLY the container names, IPs, PIDs, and values shown in Ground Truth above. Do NOT invent, guess, or substitute any names.`
              : prompt;
            ```
         j. Keep the existing rollingContext logic for idle connection PIDs (append after contextBlock)
       - Remove the old `discoveryContext` variable usage for prompt building -- the ContextManager now handles this. BUT keep `discoveryContext` for the audit log and for passing to the planning phase (they still need the raw TOON-encoded context).
       - CRITICAL: Do NOT change the planning phase integration or the execution phase. Only the prompt assembly for diagnosis changes.
  </action>
