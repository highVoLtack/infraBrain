Purpose: UX-01 requires history to default to the most recent session. UX-02 requires `--session last` to resolve to the latest session_id. Together these make history the admin's primary post-fix review tool with zero-friction access to the latest session.

   ```typescript
   if (req.query.list === 'true') {
     const sessions = deps.store.getSessionList(limit ? parseInt(limit, 10) : 20);
     res.json({ sessions, count: sessions.length });
     return;
   }
   ```

   b. Add session alias resolution BEFORE building filters:
   ```typescript
   if (session === 'last' || session === 'previous') {
     const resolved = deps.store.getSessionIdByAlias(session);
     if (!resolved) {
       res.status(404).json({ error: `No session found for alias '${session}'` });
       return;
     }
     filters.sessionId = resolved;
   } else if (session) {
     filters.sessionId = session;
   }
   ```
   This keeps the API backward-compatible: no `session` param = all entries (unchanged behavior). The CLI sends `?session=last` to implement the default-to-latest UX (see Task 2).
