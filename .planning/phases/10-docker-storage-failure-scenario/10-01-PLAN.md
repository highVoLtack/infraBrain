  <action>
Create demo/docker-storage/ directory structure following the Chaos Library pattern from Phase 9.

**docker-compose.yml:**
- Define a named volume `shared-tmpfs` with `driver: local` and `driver_opts: type: tmpfs, o: "size=10m", device: tmpfs`. This is CRITICAL — per-service `tmpfs:` declarations are NOT shared between containers. Must use named volume with tmpfs driver.
- Service `logger`: build from `./logger`, container_name `storage-logger`, mounts `shared-tmpfs:/shared`
- Service `redis`: image `redis:7-alpine`, container_name `storage-redis`, command `redis-server --save 1 1 --dir /shared --dbfilename dump.rdb --stop-writes-on-bgsave-error yes`, ports `6380:6379`, mounts `shared-tmpfs:/shared`
- Redis `--save 1 1` ensures RDB save attempt every second with any change — this makes Redis fail fast on full disk
- Port 6380 avoids collision with local Redis on default 6379

**logger/Dockerfile:**
- `FROM alpine:3`
- COPY entrypoint.sh, chmod +x, ENTRYPOINT

**logger/entrypoint.sh:**
- `#!/bin/sh`
- `dd if=/dev/zero of=/shared/bloat.log bs=1M count=9 2>/dev/null` — fills 9MB of 10MB tmpfs instantly
- `while true; do sleep 60; done` — keeps container alive for `docker exec` diagnostics
- No dependencies, no language runtime — pure Alpine + shell

**Key research finding (RESEARCH.md):** Redis with `--stop-writes-on-bgsave-error yes` (default) will refuse writes when BGSAVE fails on full disk. It may still respond to PING. The broken state check in the reset script must verify either: (a) `redis-cli PING` fails (connection refused = Redis crashed), OR (b) `redis-cli SET test 1` fails (Redis alive but refusing writes). Test at implementation time — if Redis exits entirely, connection refused is the signal; if Redis stays alive but read-only, SET failure is the signal.

  <files>demo/docker-storage/reset-docker-storage.sh</files>
  <action>
Create `demo/docker-storage/reset-docker-storage.sh` following the reset-postgres.sh template from Phase 9.

**Script flow:**
1. `set -euo pipefail`
2. Resolve SCRIPT_DIR and COMPOSE_FILE from script location
3. Tear down: `docker compose -f "$COMPOSE_FILE" down --remove-orphans --volumes 2>/dev/null || true`
4. Start: `docker compose -f "$COMPOSE_FILE" up -d --build`
5. Poll loop (max 60s, checking every 2s = 30 iterations):
   - Check tmpfs usage: `docker exec storage-logger df /shared --output=pcent 2>/dev/null | tail -1 | tr -d ' %'` — must be >= 95
   - Check Redis health: Try `docker exec storage-redis redis-cli SET infratest 1 2>&1` — if this fails (either connection refused or MISCONF error about BGSAVE), Redis is in broken state
   - BOTH conditions must be true: tmpfs full AND Redis refusing writes/unreachable
6. On success: print "SUCCESS: Storage full ($USAGE%) and Redis broken" and exit 0
7. On timeout: print error and exit 1

Make script executable: `chmod +x`

**Important:** The dual verification (physical resource + application health) is the Verification Archetype pattern — eliminates "False Green" where disk is full but Redis hasn't noticed yet.
