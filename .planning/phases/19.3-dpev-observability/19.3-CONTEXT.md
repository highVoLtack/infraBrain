**Gathered:** 2026-04-17

<domain>
## Phase Boundary

A user who runs `debug nginx 502` feels, in real time, *what is happening, why, how long it takes, and what it costs* — and can scroll back into any completed phase to see the full stream, including command output and LLM narrative. Pure UX polish on the Phase 19.2 E2E debug flow: no new pipeline capability, only better visibility, navigation, and feedback.

**Carrying forward from earlier phases (locked, not re-asked):**
- Ink 7 + React 19 stack (Phase 19)
- 3-panel Obsidian layout — 20/55/25 split at >=120 cols (Phase 19)
- Keyboard map: `Tab` cycles panels, `↑/↓` or `j/k` navigate, `Enter` expand, `Esc` collapse/dismiss, `/` search, `s` status dashboard, `Y/N` approval (Phase 19)
- Ink `useInput` (not readline) for all keyboard capture (Phase 19)
- LanceDB as sole data source for cache + memory (Phase 19)
- Markdown renderer recommendation: handwritten micromark + mdast-util-from-markdown (19.3-RESEARCH.md)
- SSE single-connection architecture per session (Phase 19.2) — extend, don't replace
- Module-scoped Promise maps for approval gates (Phase 19.2) — reuse pattern for session summary

**Requirements (finalized during discussion):** TERM-UX01 through TERM-UX08

<decisions>
## Implementation Decisions

### Expand / Phase History (TERM-UX04, TERM-UX08)

- **D-01 — Inline accordion expand.** Completed phases collapse to 1-line summaries (existing Phase 19 pattern). Pressing Enter on a focused phase expands a detail block inline; Esc collapses. Other phases stay visible above and below. No full-screen overlay, no side-panel detail view. **Rationale:** preserves causality of DPEV flow ("what happened when"), consistent with Phase 19 accordion design, future web-UI can reuse the same structure.
- **D-02 — Expanded content shows everything.** Substatus history, streamed tokens (Markdown-rendered per UX01), executed commands with stdout/stderr preview, per-phase token usage, and per-phase elapsed time. This is the "magic" surface — no summary-only mode.
- **D-03 — Keyboard nav via `↑/↓` + `j/k` alias, `Enter` expand, `Esc` collapse.** Same map as Phase 19 session tree and entity graph. **Constraint:** focused phase MUST be visually distinct (either a brighter border color OR a prefix symbol like `▸` / `●`) so the user always knows which phase Enter will open.
- **D-04 — Session replay (UX08) shows the full stream.** Identical data shape to the live view. But **initial state = all phases collapsed** — the user gets the high-level overview first, then drills in via `j/k` + `Enter`. This is the Obsidian-like "document that reveals as much depth as you want" feeling. Replay is the read-only knowledge-asset view of any session from the left panel's Sessions list.

### Activity Indicator & Sub-Status (TERM-UX03)

- **D-05 — Spinner + Substatus-Label, immediate on phase start.** Every active phase shows `⟁ LABEL` from second zero — no 3s or 5s grace period. In a professional ops tool, information beats animation: the user needs to know *which stage is active and which model is bearing the load* (Gemini Pro vs. local 122B).
- **D-06 — Labels include Meta-Aktionen, not just LLM calls.** Sub-status covers pipeline-internal steps like `"Routing skill..."`, `"Calling gemini-2.5-pro (structured object)"`, `"Parsing response"`, `"Falling back to free-text"`, `"Searching MemPalace..."`, and future-ready `"Distilling logs (Caveman)..."`. Makes the system feel *methodical*, not merely API-bound.
- **D-07 — Backend-sourced via new `dpev:substatus` SSE event.** Pipeline emits granular substatus events; UI renders whatever backend sends. No static frontend-only labels (too coarse) and no hybrid (too complex). Forward-compatible for additional stages.
- **D-08 — Timer coloring: Cyan for LLM phases (routing/discovery/diagnosis/plan), Yellow for Execution, dimmed gray when complete.** Active phase's timer is bold + colored and ticks visibly every second. Completed phases fade to dim. Goal: `htop` / `terraform` instrumentation feeling — a high-precision cockpit, not a log file.

### Token Usage Display (TERM-UX06)

- **D-09 — Per-phase usage line, inline under phase header, dimmed.** Format: `in:1687 · out:1490 · total:3177 · $0.0089 · 21.3s`. Visible even in collapsed state so the cost signal is always perceptible. **Future-ready:** the line leaves room for v2.0 Caveman metrics (`distilled: 400 · saved: 75%` alongside the base figures).
- **D-10 — Dollar cost shown alongside tokens.** Pricing comes from a new `src/config/pricing.ts` abstraction — a table keyed by model id with `inputPer1k` and `outputPer1k` rates. Render code never hardcodes prices. v2.0 extends this table with `savedViaMemory` and `savedViaCompression` computations. **Rationale:** makes the economic value of the Intelligence Layer (Phase 16 cache, Phase 17 memory, future Caveman) measurable at every interaction.
- **D-11 — Dash placeholders for undefined usage fields.** Gemini's streaming endpoint returns no usage payload — we render `in:1687 · out:– · total:– · $–` instead of hiding fields or showing "undefined". **Fallback that keeps the in-tokens count live:** use the existing `@lenml/tokenizer-qwen3` tokenizer (we know the prompt we sent, so we can count input tokens locally). Only the output side and cost fall back to `–` when the API stays silent. Keeps the UI stable (no jumping lines).
- **D-12 — Cumulative session usage in footer.** Below "Session complete (sessionId)" render `Session: X tokens · $Y.ZZ`. Backend SessionManager emits a final `dpev:session_summary` SSE event at the end of each session with aggregated totals. **Future-ready field:** payload includes `potentialSavings: number | null` — in v1.3 always `null`, rendered as dimmed `Saved via Memory: $0.00 (v2.0)`. Same field gets filled with real numbers once v2.0 Caveman + Dual-Retrieval ship.

### Status Dashboard Live Data (TERM-UX05)

- **D-13 — All four data categories live.** Cache Stats (hit rate, total entries, avg confidence), Memory Stats (incidents, entities, WAL size), Context Window (live session tokens / max, percentage), Model Assignments (role → model map). **Rationale:** the dashboard is the Company OS' nervous center; partial visibility breaks trust. Backend `src/api/routes/status.ts` must be extended to aggregate from `ContextManager`, `LanceStore` (cache + memory stores), and `InferenceScheduler`.
- **D-14 — Live poll every 2-3s while overlay open; stop when dismissed.** Resource-conscious ("poll only while visible") and cockpit-alive at the same time. Verifies trust: the user *sees* the system breathing. v2.0 "Memory Density" and "Saved Costs" metrics will animate here as the nano-LLM works in the background — a transparent "Glass Box" rather than a black box.
- **D-15 — Granularity: cumulative AND "this session".** Every stat shows two rows: all-time (long-term ROI proof) and current-session (immediate feedback during work). Psychologically important — the user sees `"This session: 2 cache hits saved 2 LLM calls"` in addition to `"All-time: 47 entries, 23% hit rate"`. v2.0 extends with `"Tokens saved this session: 45k"` via Caveman.
- **D-16 — Latest-call detail row at the top of the overlay.** Shows the most recent LLM call: model id, input/output tokens, latency ms, dollar cost. Essential for debugging performance in the hybrid Gemini + local setup. Fills the gap between per-phase (in-stream) and cumulative (total) views.

### Execution Step Visibility (TERM-UX02) — Data Wiring Fix

Scope note: this is a data-wiring bug, not a component build. `StepCard.tsx` already expects `command`, `risk`, `target`, `stdout`, `stderr`. Backend already emits them on `exec:step`. Frontend just needs to propagate them.

- **D-17 — Frontend SSE handler reads all step fields.** `src/ui/hooks/useDPEV.ts` currently pulls only `stepIndex, status, stdout, stderr` out of the `exec:step` event and drops `command, risk, target`. Fix: pass all fields through the `STEP_UPDATE` action and populate them in the `StepState` reducer case. No new component; `StepCard` renders them as-is.
- **D-18 — Initial pending events also carry command + risk.** Backend already sends them at `stream-debug.ts:370-378` for all steps when the plan is approved, so the placeholder `[1/0] ✓ []` view is gone the moment the first event arrives.

### Markdown Renderer (TERM-UX01)

- **D-19 — Handwritten micromark + mdast-util-from-markdown.** Per 19.3-RESEARCH.md recommendation. Bundle ~307 KB, Ink-native components, no ANSI boundary, clean snapshot tests. Third-party ANSI libraries (`marked-terminal`, `ink-markdown`, `@inkkit/ink-markdown`, `cli-markdown`) all disqualified on either bundle size or maintenance status.
- **D-20 — Streaming boundary: switch `StreamingText` → `MarkdownView` on `phase.status === 'complete'`.** During active token streaming mid-sentence Markdown produces noisy AST output; keep the plain streaming view until the phase finalizes, then rerender as proper Markdown. The expanded-phase view (D-02) uses `MarkdownView` exclusively.
- **D-21 — `MarkdownView` covers six feature groups.** Headings (h1-h6 styled bold + colored), inline code (dim background tint), fenced code blocks (monospace + indent), ordered/unordered lists (indent + bullet), bold/italic (Ink styling), plain-text passthrough. Snapshot tests cover all six (strip-ansi already available as transitive dep).

### Flicker-Free Re-Render (TERM-UX07)

- **D-22 — Key-stable Ink components throughout DPEV panel.** Investigate current re-render sources in `DPEVPanel`, `StepCard`, `DPEVPhaseHeader`. Primary suspect: list items without stable `key` prop. Secondary: state updates that mutate the full phase array rather than splicing. Fix both during execution — this is diagnostic + surgical rather than a feature build.

### v2.0 Placeholder Schubladen (cross-cutting)

These are rendered in v1.3 as dimmed / `v2.0` placeholders so the final visual layout is locked in *now*, and v2.0 Caveman/Dual-Retrieval can fill actual values without any UI change.

- **D-23 — `memoryStats` extended in `/status` payload.** New fields: `compressionRatio` (float | null), `totalTokensSaved` (number | null), `distilledEntriesCount` (number | null). In v1.3 always `null`. Frontend renders dedicated dashboard section **"Intelligence Efficiency"** with `"Memory Density: — (v2.0)"`. Same fields get filled by v2.0 Caveman pipeline.
- **D-24 — `dpev:session_summary` event carries `potentialSavings`.** Nullable number. v1.3 = `null`. Footer renders `"Saved via Memory: $0.00 (v2.0)"` dimmed. Slot reserved for v2.0.
- **D-25 — Per-phase usage line reserves space for compression columns.** Layout: `in:X · out:Y · total:Z · $W · Ns · [distilled: — | saved: — (v2.0)]`. The bracketed suffix is dimmed in v1.3; v2.0 fills it.
- **D-26 — Substatus label set includes future strings.** `"Distilling logs (Caveman)..."`, `"Compressing memory..."` are whitelisted in the frontend switch/rendering (not dead code; they just never fire in v1.3 because the pipeline doesn't emit them yet). Ready to light up when v2.0 backend ships.

### Claude's Discretion

- Spinner character set (reuse `@inkjs/ui` Spinner from Phase 19 — don't reinvent)

- Visual treatment of the focused phase indicator: brighter border vs. prefix symbol vs. both (designer's call during execution)
- Poll interval precise timing (2s vs 2.5s vs 3s) — test empirically

<specifics>
## Specific Ideas

- **"Obsidian callout" feeling for expanded phases** — expand looks like a document that reveals more text in-place, not a modal that interrupts.
- **"Raumschiff-Cockpit" / "Glass Box" for dashboard** — pulsing live metrics, user watches the system being efficient.
- **htop / terraform instrumentation aesthetic for timers + colors** — precise, professional, not flashy.
- **"Searching MemPalace..." substatus is a magic line** — even in v1.3 where memory search doesn't have a dedicated UI phase, seeing that label fire during diagnosis makes the Intelligence Layer perceivable.
- **v2.0 placeholders should feel intentional, not missing** — dimmed "Memory Density: — (v2.0)" is better than absence, because it shows this is where the Caveman optimization will appear.
- **Admin sees "This session saved 2 LLM calls via cache"** — cumulative+session split (D-15) should make individual-interaction wins visible, not just yearly ROI.
- **"Saved via Memory: $0.05" after v2.0** — the economic proof of the Intelligence Layer is a first-class display citizen.

</specifics>
