# Phase 19.3 Plan 05: StatusOverlay "Glass Box" Cockpit Summary

The `s`-key overlay stopped being a one-shot snapshot: it now polls every 2.5s, opens with a
latest-call detail row, splits cache stats into all-time and this-session, and reserves a named
Intelligence Efficiency section for the v2.0 Caveman metrics.

## What Was Built

**Task 1 — parseOverlayData + StatusOverlay** (`360b758` RED, `81d9930` GREEN)

`OverlayData` gained three field groups, all with locked shapes:

| Field | Source in v1.3 | Fills later |
|-------|----------------|-------------|
| `cacheBreakdown.cumulative` | `/status` → `cache` (mirrors `cacheStats`) | already real |
| `cacheBreakdown.thisSession` | `{ hits: 0, llmCallsSaved: 0 }` | backend per-session cache aggregation |
| `memoryStats.{compressionRatio,totalTokensSaved,distilledEntriesCount}` | `/status` → `memory` (always `null`) | v2.0 Caveman pipeline (D-23) |
| `latestCall` | `/status` → `latestCall` (absent today → `undefined`) | backend latest-call surface (D-16) |

`parseOverlayData`'s second parameter is now a named `StatusResponseShape` covering the whole
Plan 02 response. Two private helpers — `num(value, fallback)` and `numOrNull(value)` — sit at the
parse boundary so a malformed section degrades to a sane default rather than reaching the frame.
`latestCall` is normalized only when `modelId` is a string; anything else yields `undefined`, so a
garbage payload renders the "No LLM calls yet" line instead of a half-populated row.

The `useEffect` keeps its `cancelled` flag and adds `setInterval(…, POLL_INTERVAL_MS)` with
`clearInterval` in the cleanup — the `SessionPanel.tsx` pattern at a 2.5s cadence instead of 10s.

Rendering, top to bottom: `STATUS DASHBOARD` header → **Latest Call** → Backends → Model
Assignments → **Cache Stats (Cumulative / This Session)** → Memory Stats → **Intelligence
Efficiency** → Context Window. Every unknown figure is an em-dash, never a `0` or `$0.0000`:

```
Latest Call
  qwen3-32b · in:900 · out:— · 120ms · $—

Cache Stats
  Cumulative:   Hit Rate 23.0%  ·  Entries 47  ·  Avg Confidence 81.0%
  This Session: 0 hits  ·  0 LLM calls saved

Intelligence Efficiency
  Memory Density: — (v2.0)
  Tokens Saved: — (v2.0)
  Distilled Entries: — (v2.0)
```

Backends, Model Assignments, Context Window, the progress bar, the `inferenceMode`/border/padding
styling and Esc-dismiss are byte-identical in behavior — locked in by an explicit regression test.

17 tests in a new `StatusOverlay Phase 19.3 (TERM-UX05)` block in `tests/ui/layout.test.tsx`.

## Key Decisions

**`latestCall` is parsed, not hardcoded `undefined`.** The plan says to leave it undefined because
`/status` does not surface it yet. Written that way, the field is unreachable: the populated render
branch has no input, so the plan's own test #7 concedes it may have to be skipped. Reading
`statusResponse.latestCall` when present costs six lines, makes the branch testable today, and is
exactly what the phase's "locked visual layout" principle is for — the backend can start emitting
the field with zero UI change. The absent case still yields `undefined`, so v1.3 behavior is
unchanged.

**Coercion helpers instead of `??`.** The plan's snippets use `mem?.compressionRatio ?? null`. `??`
only catches `null`/`undefined` — a string, an array or a `NaN` passes straight through into a
template literal and prints as itself. `/status` wraps every section in its own try/catch and can
legitimately return a partially-built object, and the graceful-degradation requirement is explicit
("NEVER shows the literal text `'undefined'` or `'null'`"). `num` / `numOrNull` enforce that at the
one boundary where it is checkable, and a malformed-payload test asserts the rendered frame contains
none of `undefined`, `null`, `NaN`.

**The `currentTokens` stub is resolved as a seam, not a wire-up.** Plan 03 handed over
`state.sessionSummary?.totalTokens` as the real source. That state lives inside
`LiveDPEVPanel`'s `useDPEV` call (`src/ui/panels/DPEVPanel.tsx:188`); `StatusOverlay` is rendered
from `App.tsx:396`, a sibling that never sees it. Wiring it requires lifting `useDPEV` out of
`DPEVPanel` into `App.tsx` — an architectural change (Rule 4) in two files owned by Plans 04 and 06.
What this plan can do inside its own file, it did: `StatusOverlay` takes an optional
`sessionTokens?: number` that overrides `contextWindow.current` and recomputes the bar percentage.
Supplying it is a one-line change at the call site. Covered by a test asserting
`8192 / 32768 tokens` and `25%`. See Known Stubs.

## Known Stubs

**`cacheBreakdown.thisSession` renders `0 hits · 0 LLM calls saved`.** No backend surface exposes
per-live-session cache hits; `/status` aggregates the LanceDB cache table, which is all-time by
construction. Locked shape per the phase's visual-layout principle. **Resolved by:** a future
backend pass adding a session-scoped cache counter (the natural home is
`src/state/session-usage.ts`, which already keys by `sessionId`). The UI needs no change.

**`memoryStats.compressionRatio` / `totalTokensSaved` / `distilledEntriesCount` render `—`.**
Deliberate per D-23 — `/status` always sends `null` in v1.3. The wiring is proven by a test that
feeds `0.72 / 45000 / 12` through `parseOverlayData` and asserts they surface. **Resolved by:** the
v2.0 Caveman distillation pipeline.

**`latestCall` is never populated in v1.3.** `/status` does not emit the field, so the overlay shows
`No LLM calls yet`. The parse and render paths are complete and tested; only the producer is
missing. **Resolved by:** a backend pass recording the most recent LLM call (the data already exists
in the `dpev:usage` payload — it just is not retained anywhere `/status` can read it).

**Context Window shows `0 / 32768` unless `sessionTokens` is passed.** Plan 02's stub, inherited.
Not closed here because the live figure is inside `DPEVPanel`'s hook state and lifting it is a
Rule 4 architectural change in Plan 04/06's files. The consumer side is done: pass the prop and the
bar is live. **Resolved by:** whichever plan lifts DPEV state to `App.tsx`.

## Threat Flags

None. This plan touches one client-side Ink component. No new network endpoints (it polls two
pre-existing localhost GETs it already called), no auth paths, no file access, no schema at a trust
boundary. The one input-validation surface — untrusted-shaped JSON from `/status` — is now *more*
defensive than before: every numeric field is coerced at the parse boundary and `latestCall` is
rejected outright unless `modelId` is a string.
