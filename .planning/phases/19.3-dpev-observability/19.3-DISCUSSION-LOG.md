## Expand / Phase History (UX04 / UX08)

### Expand style

| Option | Description | Selected |
|--------|-------------|----------|
| Inline expand (Accordion) | Phase-header stays, content expands inline, other phases still visible, Obsidian-callout feel | ✓ |
| Full-screen overlay | Full-screen modal, Esc closes, more space but loses DPEV-chain context | |
| Side-panel detail view | Details render in right panel, pushes Entities aside | |

**User's choice:** Inline expand (Accordion)
**Notes:** "Das entspricht unserer Obsidian-Vision: Die Diagnose ist ein lebendiges Dokument. Auch im Hinblick auf eine zukünftige Web-UI ist das Accordion-Modell am besten skalierbar und bewahrt die Kausalität des DPEV-Flows. Der Nutzer soll die Details genau dort sehen, wo sie passiert sind, ohne den Blick auf die gesamte Kette zu verlieren."

### Expanded content

| Option | Description | Selected |
|--------|-------------|----------|
| Alles: Sub-status, Token-Stream, Commands, Output, Usage | Full transparency, Magie spüren | ✓ |
| Nur LLM-Output (Diagnosis / Plan Markdown) | Minimal, for re-reading | |
| Nur Commands + Output (keine Narrative) | Technical focus only | |

**User's choice:** Alles: Sub-status, Token-Stream, Commands, Output, Usage

### Keyboard navigation

| Option | Description | Selected |
|--------|-------------|----------|
| ↑/↓ + Enter/Esc (j/k Vim-alias) | Phase 19 keyboard map consistency, power-tool feeling | ✓ |
| Mouse/Click only | Natural for non-Vim users, breaks keyboard-first design | |
| Number keys 1-6 per phase | Fast but conflicts with session-select | |

**User's choice:** ↑/↓ + Enter/Esc (j/k Vim-alias)
**Notes:** "Konsistenz ist das wichtigste UX-Prinzip für InfraBrain. Achte darauf, dass die 'fokussierte' Phase visuell deutlich hervorgehoben wird (z.B. durch einen helleren Rahmen oder ein Präfix-Symbol), damit der Nutzer weiß, welche Phase er mit Enter gerade aufklappt."

### Session replay depth (UX08)

| Option | Description | Selected |
|--------|-------------|----------|
| Full stream identical to live view | All phases, commands, outputs, tokens, usage — "volle Wahrheit" | ✓ |
| Summary + selectively expand | Loads collapsed, user expands manually | |
| Header + outcomes only, no streams | Lightweight audit view, loses magic | |

**User's choice:** Full stream identical to live view
**Notes:** "Ein Replay muss die 'volle Wahrheit' abbilden, um als verlässliches Knowledge Asset im Company OS zu dienen. Beim Öffnen eines Replays alle Phasen eingeklappt, damit der User erst den Überblick hat, aber mit j/k und Enter sofort in jede Tiefe abtauchen kann. Exakt das Obsidian-Feeling."

## Activity Feedback (UX03)

### Activity indicator type

| Option | Description | Selected |
|--------|-------------|----------|
| Spinner + Substatus-Label | "⟁ Calling gemini-2.5-pro…" — information-first | ✓ |
| Spinner + Live Token Counter | "⟁ Thinking… 1243 tokens" — ChatGPT feel, inconsistent without streaming | |
| Animated dots only | Minimal but uninformative | |

**User's choice:** Spinner + Substatus-Label

### Threshold

| Option | Description | Selected |
|--------|-------------|----------|
| Sofort bei Phase-Start | Always consistent, no empty waiting | ✓ |
| Nach 3s | Short phases clean, long phases get spinner | |
| Nach 5s | Aggressive, perhaps too hesitant for "Magie spüren" | |

**User's choice:** Sofort bei Phase-Start
**Notes:** "In einem professionellen Ops-Tool ist 'Information' wichtiger als 'Animation'. Der User muss sehen, welche Stufe der Pipeline gerade aktiv ist und welches Modell die Last trägt. Das Label soll auch 'Meta-Aktionen' anzeigen, wie 'Distilling logs...' oder 'Searching MemPalace...'. Das gibt dem User das Gefühl, dass das System methodisch vorgeht, anstatt nur auf eine API-Antwort zu warten."

### Sub-status source

| Option | Description | Selected |
|--------|-------------|----------|
| Backend emits dpev:substatus events (new) | Precise, future-proof for more steps | ✓ |
| Frontend static label per phase | No backend change, less accurate | |
| Hybrid: default label + optional backend override | Best-of-both, more complex | |

**User's choice:** Backend emits dpev:substatus events (new)

### Timer visibility

| Option | Description | Selected |
|--------|-------------|----------|
| Bold+color while active, dim when complete | htop/terraform feeling, live counter | ✓ |
| Larger font / own line | More space but breaks compact layout | |
| Keep current look | If focus + expand is enough | |

**User's choice:** Bold+color while active, dim when complete
**Notes:** "Ein tickender, farbiger Counter ist das beste visuelle Feedback für langlaufende Prozesse. Unterschiedliche Farben für den aktiven Counter: Cyan für LLM-Diagnosen und Gelb für die Befehlsausführung (Execution). Sobald eine Phase abgeschlossen ist, wird der Counter grau/dimm. Hochpräzises, instrumentiertes Gefühl wie bei Profi-Tools (htop, terraform)."

## Token Usage Rendering (UX06)

### Usage location

| Option | Description | Selected |
|--------|-------------|----------|
| Inline under phase header, dimmed | Compact, always visible even collapsed | ✓ |
| Badge next to timer | Very compact but loses in/out split detail | |
| Only in expanded phase | Clean collapsed view but hides cost | |

**User's choice:** Inline under phase header, dimmed
**Notes:** "Transparenz über die Token-Nutzung ist für das Vertrauen in ein autonomes System unerlässlich. Diese Zeile ist strategisch wichtig für unsere Nano-LLM/Caveman-Strategie. Wir werden hier später die Ersparnis visualisieren (z.B. 'distilled: 400 | saved: 75%'). Das macht die technische Effizienz von InfraBrain direkt im UI greifbar, selbst wenn der Nutzer die Details gerade nicht expandiert hat."

### Dollar cost

| Option | Description | Selected |
|--------|-------------|----------|
| Yes, tokens + $ side-by-side | Makes caching/memory ROI measurable | ✓ |
| Tokens only | Simpler but loses business relevance | |
| Toggle, tokens default | Compact, but magic not passively sensed | |

**User's choice:** Yes, tokens + $ side-by-side
**Notes:** "Die Anzeige der Kosten macht den ökonomischen Vorteil unserer Caching- und Memory-Strategien sofort sichtbar. Implementiere eine einfache pricingTable in der globalen Konfiguration, die Kosten pro 1k Tokens für Input/Output pro Modell definiert. Wenn wir später die Caveman-Kompression aktiv haben, soll die UI nicht nur die aktuellen Kosten zeigen, sondern auch die 'Gesparten Kosten durch Kompression'. Das macht InfraBrain zum Helden der IT-Budget-Planung."

### Undefined handling

| Option | Description | Selected |
|--------|-------------|----------|
| Dash placeholder for undefined fields | Consistent line, no layout jump | ✓ |
| Hide the field completely | Clean but inconsistent | |
| "usage unavailable (streaming)" | Technically honest, verbose, negative vibe | |

**User's choice:** Dash placeholder for undefined fields
**Notes:** "UI-Stabilität hat Vorrang; wir wollen keine springenden Zeilen im Terminal. Nutze unseren lokalen Token-Counter (@lenml/tokenizer-qwen3) als Fallback für die Input-Tokens. Selbst wenn Gemini beim Streaming keine Usage-Daten mitschickt, kennen wir den Prompt. Wir können die in-Tokens also lokal exakt berechnen. Nur für die out-Tokens nutzen wir dann den Dash-Placeholder."

### Cumulative session usage

| Option | Description | Selected |
|--------|-------------|----------|
| Footer: Session X tokens · $Y | Shows total cost per debug session | ✓ |
| Per-phase only | Simpler but loses ops insight | |
| Only in status dashboard | Clean but not passively perceivable | |

**User's choice:** Footer: Session X tokens · $Y
**Notes:** "Wir brauchen die kumulierte Sicht, um den Wert von InfraBrain als effizientes Expertensystem zu beweisen. Implementiere die Berechnung im Backend innerhalb des SessionManager. Sobald eine Session beendet oder pausiert wird, soll eine finale dpev:session_summary Nachricht über SSE gesendet werden. Bereite die Datenstruktur so vor, dass wir hier später auch die 'Total Savings' durch unsere Caveman-Kompression und den LanceDB-Cache anzeigen können (z.B. 'Session Cost: $0.01 | Saved: $0.05 via Memory')."

## Status Dashboard Live Data (UX05)

### Which fields live

| Option | Description | Selected |
|--------|-------------|----------|
| Cache Stats | hit rate, total entries, avg confidence from Phase 16 | ✓ |
| Memory Stats | incidents, entities, WAL size from Phase 17 | ✓ |
| Context Window | live session tokens / max, tied to Phase 15 auto-compact | ✓ |
| Model Assignments | role → model map, essential for mixed-provider setups | ✓ |

**User's choice:** All four
**Notes:** "Das Dashboard ist das Nervenzentrum unseres Company OS. Wir brauchen die volle Sichtbarkeit über alle Intelligenz-Layer, um Vertrauen und Kontrolle zu gewährleisten. Erweitere den Backend-Endpoint src/api/routes/status.ts so, dass er diese Daten aggregiert aus dem ContextManager, LanceStore und InferenceScheduler liefert. Integriere im Bereich 'Context' bereits den Platzhalter für die 'Compression Density' (Caveman). Das Dashboard soll sich anfühlen wie das Cockpit eines Raumschiffs, das seine eigene Effizienz live optimiert."

### Refresh mode

| Option | Description | Selected |
|--------|-------------|----------|
| Live-poll every 2-3s while open | Cockpit-alive, poll scoped to overlay visibility | ✓ |
| Snapshot on open, static | Simpler, user must reopen to refresh | |
| Live-poll + pulse animation on updates | Best UX, most work | |

**User's choice:** Live-poll every 2-3s while open
**Notes:** "Ein 'Company OS' muss pulsieren. Polling nur aktiv solange das Overlay sichtbar ist. Es verwandelt InfraBrain von einer 'Black Box' in eine transparente 'Glass Box', in der man der KI beim effizienten Arbeiten zusehen kann."

### Granularity

| Option | Description | Selected |
|--------|-------------|----------|
| Cumulative since project start | Lifetime stats from LanceDB, simplest | |
| Cumulative + "This Session" | Both metrics, richer feedback | ✓ |
| "This Session" only | Too narrow for long-term ROI | |

**User's choice:** Cumulative + "This Session"
**Notes:** "Wir brauchen beide Metriken. Session-Tracking im Backend-State. Psychologisch wichtig für den User zu sehen: 'In dieser Session wurden bereits X LLM-Calls durch den Cache gespart'. Das ist die perfekte Vorbereitung für v2.0."

### Latest LLM call detail

| Option | Description | Selected |
|--------|-------------|----------|
| Yes: model, tokens, latency, cost | Fills gap between per-phase and cumulative | ✓ |
| No, redundant to per-phase | Minimalistic | |

**User's choice:** Yes: model, tokens, latency, cost
**Notes:** "Das Dashboard muss die harten Fakten der letzten Inferenz liefern. Latenz und Modell-Identität sind für das Debugging der Performance in unserem hybriden Setup unverzichtbar. Modellname, Latenz in ms, Token-Usage (In/Out) und die berechneten Kosten."
