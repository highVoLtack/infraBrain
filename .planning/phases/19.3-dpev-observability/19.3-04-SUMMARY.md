# Phase 19.3 Plan 04: DPEVPanel Observability Wiring Summary

The glue plan. Waves 1–3 built a Markdown renderer with no call sites, five reducer actions with no
readers, and a phase header with an empty substatus slot; this plan makes all three visible on
screen and navigable by keyboard.

## What Was Built

**Task 1 — DPEVPanel wiring** (`bc93d51` RED, `7dd3fab` GREEN)

Five exported pure helpers now sit beside the existing `shouldShowCacheHitBanner` /
`getApprovalType` pair, following the same file convention (PATTERNS.md line 191):

| Helper | Contract |
|--------|----------|
| `virtualFocusedIndex(state)` | `focusedPhaseIndex ?? last phase index`, `-1` when the list is empty |
| `isPhaseInputActive(state)` | `false` whenever `pendingApproval` is set or status is `awaiting-approval` / `plan-approval` |
| `handlePhaseInput(state, input, key, dispatch)` | ↑/k, ↓/j, Enter, Esc → `PHASE_FOCUS` / `PHASE_EXPAND` |
| `formatUsageLine(usage)` | the D-09/D-11/D-25 string, or `undefined` when the phase reported nothing |
| `PhaseInputKey` | the four-field subset of Ink's `Key` the map reads |

`DPEVPanelContent`'s phase map gained four things per phase: a focus-cursor `Text` (`▸ ` cyan when
focused, two spaces otherwise) preceding the header, `substatus={phase.substatus}` threaded to
`DPEVPhaseHeader`, a dimmed usage row, and a body that is now a three-way ternary — active phases
keep `StreamingText`, completed-and-expanded phases render `MarkdownView`, everything else renders
nothing. The container key moved from `phase-${i}` to `phase-${phase.name}-${phase.startedAt}`.

The usage row reads, with a Gemini-style silent provider:

```
  ⟁ Calling gemini-2.5-pro (structured object)
  in:1687 · out:– · total:– · $– · [distilled: — | saved: — (v2.0)]
```

The completion footer became a column and gained two dimmed lines under `Session complete`:
`Session: {N} tokens · ${X.XX}` and `Saved via Memory: ${Y.YY} (v2.0)`, both suppressed when
`sessionSummary` is undefined.

`LiveDPEVPanel` registers one `useInput` that delegates to `handlePhaseInput`, gated by
`{ isActive: isPhaseInputActive(state) }`.

35 tests in two new describe blocks in `tests/ui/dpev-panel.test.tsx`.

## Key Decisions

**The keyboard map is a pure function, not an inline `useInput` closure.** The plan's STEP C writes
the map directly inside `LiveDPEVPanel`. Written that way it is untestable: `LiveDPEVPanel` calls
`useDPEV` → `useSSE` → `EventSource`, so mounting it in a test needs an SSE harness this file does
not have, and the plan's own STEP E concedes the input tests may have to be skipped and the D-03
behaviour left to "the reducer-level tests from Plan 03". But the reducer tests cover
`PHASE_FOCUS`/`PHASE_EXPAND` *given an action* — they say nothing about which keystroke produces
which action, which is the entire content of D-03. This is structurally the same gap that let D-17
survive into Plan 03 (`handleSSEEvent` was a closure, so routing was never tested while the reducer
was tested twice). Extracting the map costs nine lines and buys 11 tests over the exact contract:
`k` and `↑` agree, `j` and `↓` agree, Enter skips active phases, Esc always collapses, an empty
phase list dispatches nothing.

**Bounds clamping stays in the reducer.** `handlePhaseInput` dispatches `currentIdx - 1` even when
that is `-1`. Plan 03's `PHASE_FOCUS` already clamps to `[0, phases.length - 1]`, and duplicating
the rule in the caller means two places to keep in sync. Locked by a test that asserts both halves:
the handler emits `index: -1`, and `dpevReducer` turns it into `0`.

**Enter does nothing on an active phase.** D-20 keeps a streaming phase on `StreamingText`, so
"expanded" has no meaning for it — the body is already fully visible. Silently ignoring Enter is
better than setting `expandedPhases[i] = true` on a phase whose render path ignores the flag, which
would leave the phase mysteriously pre-expanded the instant it completes.

**Esc is wired even though `App.tsx` currently swallows it.** See Deviations — the panel-side
contract is what this plan owns and it is correct; the arbitration is Plan 06's.

## Deviations from Plan

- **Rationale:** covered in Key Decisions above. Net effect is +11 tests over behaviour the plan
  was prepared to leave uncovered.
- **Files modified:** `src/ui/panels/DPEVPanel.tsx`
- **Commit:** `7dd3fab`

**2. Test list is 35 cases against the plan's ≥10**

Beyond the plan's enumerated ten: usage line visible while the body is collapsed (the D-09
"cost signal is always perceptible" clause, which nothing else asserted); no usage row at all when
`phase.usage` is absent; an active phase with `expandedPhases[i] = true` still refusing to double-
render through MarkdownView; a non-null `potentialSavings` surfacing as `$1.50` (proving the v2.0
slot is wired, not hardcoded); `isPhaseInputActive` false for a cache-hit approval, which has
`status: 'awaiting-approval'` but no `pendingApproval` and would slip through a `pendingApproval`-only
guard; and the eleven keyboard-map cases.

### Corrections to the Plan's Own Assertions

**3. [Rule 1 - Bug] The plan's test 2 expects `$0.0038` for a cost of `0.00375`**

- **Found during:** Task 1 (RED)
- **Issue:** `(0.00375).toFixed(4)` is `"0.0037"`, not `"0.0038"` — `0.00375` has no exact binary
  representation and lands just below the midpoint, so `toFixed` rounds down. The plan's expected
  value would have failed against a correct implementation.
- **Fix:** used `costUsd: 0.0089` (the figure from D-09's own example) and asserted `$0.0089`,
  which is unambiguous under any rounding mode.
- **Files modified:** `tests/ui/dpev-panel.test.tsx`
- **Commit:** `bc93d51`

### Scope Boundary — Not Fixed

**4. `App.tsx` swallows `Esc` and leaks `j`/`k` into the command box.** Logged to
`deferred-items.md` (`4179884`). Ink fires every registered `useInput` handler for a keystroke —
they are not exclusive — so `DPEVPanel` cannot suppress a sibling's handler from its own file:

- `App.tsx:337-340` treats `Esc` as "exit the live session". The panel's collapse dispatch does
  fire, but the panel unmounts on the same keystroke, so the collapse is never seen.
- `CommandInput` is mounted with `isActive={!showStatusOverlay}` (`App.tsx:404`), so with an empty
  prompt box `j` and `k` fall through `handleShortcut` into `setText(t => t + input)` and are typed
  into the command field.

`↑`, `↓` and `Enter` are clean: Ink normalises non-alphanumeric keys to `input = ''`
(`node_modules/ink/build/hooks/use-input.js:91-93`), so `CommandInput` ignores them, and App's
global handler does not read arrows. The fix is an arbitration change in `src/ui/App.tsx` — Plan
06's declared scope, and 19.3-04's scope fence forbids crossing into it.

**5. `StreamingText` keys its windowed lines by array index.** `StreamingText.tsx:28` maps
`visibleLines` with `key={i}` while windowing to the *last* `maxLines` entries, so every advancing
token shifts content across stable keys. This is D-22's named "secondary suspect" and a plausible
TERM-UX07 artefact source, but `StreamingText.tsx` is in no plan's `files_modified`. Logged with a
concrete fix in `deferred-items.md`. The key instability this plan *does* own — the phase list —
is fixed.

**6. `npx tsc --noEmit` remains at exactly 8 pre-existing errors.** The task's done-criteria call
for a clean run; per `deferred-items.md` that gate cannot pass and never could. File-scoped check
used instead:

```
npx tsc --noEmit 2>&1 | grep -E "DPEVPanel|dpev-panel"   → no matches
npx tsc --noEmit 2>&1 | grep -c "error TS"               → 8   (unchanged)
```

Error-bearing files are the same four as after Wave 3: `src/config/types.ts`,
`src/execution/self-healer.ts`, `src/memory/incident-store.ts`, `src/cache/lance-store.ts`.

**7. Two E2E POC failures unchanged.** `poc-nginx-502` and `poc-postgres-connleak` — no live LLM
backend, no Docker demo stack. Not touched.

**Notes for Plan 06 (`src/ui/App.tsx`, replay parity):**

1. **Keyboard arbitration is the blocker for TERM-UX04.** Gate `CommandInput`'s `isActive` on
   center-panel focus, and give the focused phase's collapse precedence over session-exit for `Esc`.
   The cleanest shape is the one `SessionPanel` already uses: thread an `activeFocus` prop into
   `DPEVPanel` and pass it through to `isPhaseInputActive`. Details in `deferred-items.md`.
2. **Replay already honours D-04.** `isExpanded` reads
   `state.expandedPhases?.[i] ?? (phase.status === 'active')`, so a replay state built with
   `expandedPhases = {}` renders every completed phase collapsed with no change to this file.
   `ReplayState`'s shape was not touched.
3. **Plan 05's `sessionTokens` seam is still open and this plan did not close it.** The live figure
   remains inside `LiveDPEVPanel`'s `useDPEV` state (`DPEVPanel.tsx`), and `StatusOverlay` is a
   sibling rendered from `App.tsx:396`. Nothing here made it naturally available — closing it still
   means lifting `useDPEV` into `App.tsx`, then passing
   `sessionTokens={state.sessionSummary?.totalTokens}`.
4. **The focus cursor renders in replay too.** With `focusedPhaseIndex` undefined,
   `virtualFocusedIndex` puts `▸` on the last phase. If Plan 06 wants replay to open with no cursor,
   that is a change to `virtualFocusedIndex`, not to the render.

## Outstanding: Human Checkpoint (Task 2)

**Task 2 of this plan is `checkpoint:human-verify` with `gate="blocking"` and is NOT satisfied.**
It requires a running server, a live LLM backend, and human judgement on subjective UX (htop-cockpit
feel, Obsidian-accordion feel, flicker-free re-render) — none of which can be evaluated from code or
tests. It was returned to the orchestrator rather than self-approved.

Two of its eight verification points are known to fail before the user looks, for reasons outside
this plan's scope (Deviation 4):

- **Step 4, `Esc`** — will exit the live session instead of collapsing the body.
- **Step 4, `j`/`k`** — will move the cursor *and* type the character into the command box.

`↑`/`↓`, `Enter`-to-expand, and steps 3, 5, 6, 7, 8 are verifiable as-is.

no UI change. **Resolved by:** v2.0.

`potentialSavings: null` (D-24). Not hardcoded — a test feeds `1.5` through and asserts `$1.50`

Plan 02's events arrive.

## Threat Flags

None. This plan touches one client-side Ink panel. No network endpoints (the three existing `fetch`
calls to `/stream/debug/*` are unchanged), no auth paths, no file access, no schema at a trust
boundary. The one new input surface — keystrokes — is *more* guarded than before:
`isPhaseInputActive` explicitly refuses to run while any approval gate is open, so the accordion can
never consume a keystroke intended as a Y/N answer to a destructive-command prompt. That guard is
covered by four tests, including the cache-hit case that a naive `pendingApproval`-only check misses.
