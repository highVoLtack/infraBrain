**Pure-function extraction pattern** (PlanView.tsx lines 24-48):
```typescript
/**
 * Pure function: extract renderable ... from a ... object.
 * Tolerates undefined, null, and malformed inputs -- returns [] instead of
 * throwing so callers can treat the input as "empty" when upstream data is
 * missing.
 */
export function renderMarkdown(input: string | undefined): React.ReactElement {
  if (!input || typeof input !== 'string') {
    return <Box flexDirection="column" />;
  }
  const ast: Root = fromMarkdown(input);
  return (
    <Box flexDirection="column">
      {ast.children.map((node, i) => renderNode(node as Content, `md-${i}`))}
    </Box>
  );
}
```

**Component wrapper + memoization** (Pitfall 1 in RESEARCH.md + useMemo pattern already used elsewhere):
```typescript
export function MarkdownView({ children }: MarkdownViewProps): React.ReactElement {
  const rendered = React.useMemo(() => renderMarkdown(children), [children]);
  return rendered;
}
```

**Replication notes:**
- Follow PlanView's defensive defaults: `fromMarkdown(undefined)` or an empty string returns an empty Box, never throws (D-21 plain-text passthrough).
- Use `theme.ts` color tokens (cyanBright, greenBright, yellowBright) but prefer adding new theme constants (`markdownH1`, `markdownCode`, `markdownInlineCode`) per Open Question #2 in RESEARCH.md rather than hardcoding.
- Recursive `renderNode` helper: keys of form `${parentKey}-${index}` (see Pitfall 5 in RESEARCH.md for key collision scope).

### `src/config/pricing.ts` (new config, pure lookup)

**Analog:** `src/config/types.ts` + `src/config/defaults.ts`

**Rationale:** Config files in this project use (a) zod schema with `.default()` for each field, (b) exported `type X = z.infer<...>`, (c) a companion `defaults.ts` that parses the schema to produce a constant. Pricing follows this shape: a keyed table with per-model rates + helper functions for cost computation.

**Schema pattern** (`src/config/types.ts` lines 6-14):
```typescript
import { z } from 'zod';

export const PricingEntrySchema = z.object({
  inputPer1k: z.number().default(0),
  outputPer1k: z.number().default(0),
});
export type PricingEntry = z.infer<typeof PricingEntrySchema>;

export const PricingTableSchema = z.record(z.string(), PricingEntrySchema);
export type PricingTable = z.infer<typeof PricingTableSchema>;
```

**Default export pattern** (`src/config/defaults.ts` lines 1-5):
```typescript
export const DEFAULT_PRICING: PricingTable = {
  'gemini-2.5-pro':    { inputPer1k: 0.00125, outputPer1k: 0.005 },
  'gemini-2.5-flash':  { inputPer1k: 0.000075, outputPer1k: 0.0003 },
  'qwen3-32b':         { inputPer1k: 0, outputPer1k: 0 }, // local → $0
  'infrabrain':        { inputPer1k: 0, outputPer1k: 0 }, // local → $0
};
```

**Pure computation helper** (match `StatusOverlay.renderProgressBar` pure-function style, lines 111-118):
```typescript
/**
 * Pure function: compute USD cost from token counts and model id.
 * Returns null when model is not in the pricing table (graceful degradation).
 * D-11: callers render `$–` for null.
 */
export function computeCost(
  modelId: string,
  inputTokens: number,
  outputTokens: number,
  table: PricingTable = DEFAULT_PRICING,
): number | null {
  const rates = table[modelId];
  if (!rates) return null;
  return (inputTokens / 1000) * rates.inputPer1k + (outputTokens / 1000) * rates.outputPer1k;
}
```

**Replication notes:**
- `DEFAULT_PRICING` is the v1.3 baseline; v2.0 Caveman will extend (D-10).
- `computeCost` returns `number | null` — MUST NOT throw on unknown model id (graceful degradation idiom used in `IncidentStore.getStats` returning `null`, `parseOverlayData` returning 'N/A').
- Unit tests in `tests/config/pricing.test.ts` follow `tests/config/types.test.ts` describe-block style: `describe('PricingEntrySchema', ...)`, `describe('computeCost', ...)`.

**Module-scoped map + pure helpers pattern** (template):
```typescript
/**
 * session-usage - Per-session token/cost aggregator
 *
 * Accumulates token counts and dollar cost per sessionId, emits a final
 * dpev:session_summary payload at session end. Module-scoped Map mirrors
 * the approval-map pattern in src/api/routes/stream-debug.ts.
 */

import { computeCost, type PricingTable } from '../config/pricing.js';

export interface UsageTotals {
  totalInputTokens: number;
  totalOutputTokens: number;
  totalTokens: number;
  totalCostUsd: number;
}

const _usage = new Map<string, UsageTotals>();

export function recordUsage(
  sessionId: string,
  modelId: string,
  inputTokens: number,
  outputTokens: number,
  pricing?: PricingTable,
): UsageTotals {
  const current = _usage.get(sessionId) ?? {
    totalInputTokens: 0, totalOutputTokens: 0, totalTokens: 0, totalCostUsd: 0,
  };
  const cost = computeCost(modelId, inputTokens, outputTokens, pricing) ?? 0;
  const next: UsageTotals = {
    totalInputTokens: current.totalInputTokens + inputTokens,
    totalOutputTokens: current.totalOutputTokens + outputTokens,
    totalTokens: current.totalTokens + inputTokens + outputTokens,
    totalCostUsd: current.totalCostUsd + cost,
  };
  _usage.set(sessionId, next);
  return next;
}

export function getSessionSummary(sessionId: string): UsageTotals | undefined {
  return _usage.get(sessionId);
}

export function clearSessionUsage(sessionId: string): void {
  _usage.delete(sessionId);
}

export function _resetAll(): void {
  _usage.clear();
}
```
