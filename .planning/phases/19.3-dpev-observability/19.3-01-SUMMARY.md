# Phase 19.3 Plan 01: Foundation Summary

Established the Phase 19.3 foundation — TERM-UX01..UX08 requirements, the two Markdown-parser
dependencies, a null-safe LLM pricing abstraction, and a handwritten Ink-native Markdown renderer
that emits `<Box>`/`<Text>` nodes instead of ANSI strings.

## What Was Built

**Task 1 — Requirements + dependencies** (`8f0588b`)

Added a `### DPEV Panel Observability (Phase 19.3)` section to `.planning/REQUIREMENTS.md` with
eight requirements (TERM-UX01..UX08) lifted verbatim from the ROADMAP Phase 19.3 success criteria,
plus 8 traceability rows and a coverage bump from 50 to 58 mapped requirements. Installed
`micromark@^4.0.2` and `mdast-util-from-markdown@^2.0.3` — both pure ESM, matching the project's
`"type": "module"`. No disqualified library (`marked-terminal`, `ink-markdown`,
`@inkkit/ink-markdown`, `cli-markdown`) and no syntax-highlighting package was installed.

**Task 2 — Pricing abstraction** (`af88efe` RED, `44abdfd` GREEN)

`src/config/pricing.ts` exports `PricingEntrySchema`, `PricingTableSchema`, `PricingEntry`,
`PricingTable`, `DEFAULT_PRICING`, and `computeCost`. `DEFAULT_PRICING` covers `gemini-2.5-pro`,
`gemini-2.5-flash`, `qwen3-32b`, and `infrabrain` (local models at $0). `computeCost` is a pure
function returning `number | null` — **null for unknown models**, which is the whole point of the
abstraction: rendering `$0` for an unpriced model would silently lie about cost. 19 tests.

**Task 3 — MarkdownView** (`e7ea0e5` RED, `d9c5c86` GREEN)

`src/ui/components/MarkdownView.tsx` exports the `renderMarkdown` pure function and the
`MarkdownView` component. `renderMarkdown` parses with `fromMarkdown` and recursively maps MDAST
to Ink primitives: headings (bold, depth-cycled color), paragraphs, fenced code (bordered box with
a dim language label), inline code, strong, emphasis, ordered/unordered lists, and text. Unknown
node types return `null` rather than leaking raw Markdown. `MarkdownView` wraps it in
`React.useMemo` keyed on `children` so a streaming parent re-render does not re-parse the
accumulated string. 16 tests.

## Key Decisions

**Null, not zero, for unpriced models.** `computeCost` returns `null` when the model id is absent
from the table. Downstream plans render an em-dash. Returning `0` would be indistinguishable from
a genuinely free local model.

**No ANSI boundary.** The renderer produces Ink components, never pre-colored strings. This also
sidesteps chalk's non-TTY auto-disable (RESEARCH Pitfall 6): the component tree is always
exercised in tests regardless of TTY state.

**Docstring reworded to satisfy its own gate.** The plan supplied a docstring naming
`marked-terminal` / `ink-markdown` as rejected alternatives, while the same task's done-criteria
required `grep "marked\|ink-markdown" src/ui/components/MarkdownView.tsx` to return nothing —
mutually contradictory as written. Resolved by keeping the rationale but referring to
"the pre-built ANSI-string terminal renderers ... (see section 2 for the disqualified
alternatives)". The grep gate now passes and the reasoning is preserved.
