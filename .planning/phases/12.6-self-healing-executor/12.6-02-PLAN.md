Modify executor.ts to integrate self-healing:

1. **Extend ExecutionDeps in types.ts** with optional self-healing fields:
   - `correctionModel?: LanguageModel` -- model for LLM corrections
   - `skill?: SkillFile` -- active skill for allowlist + tool context
   - `rewriteRules?: RewriteRule[]` -- for dynamicRewrite on corrected commands
   - `containers?: string[]` -- discovered containers for rewriting
   These are optional so existing callers without self-healing still work.

2. **Replace CircuitBreaker call in executor.ts step loop** (lines 162-205):
   - After `parseCommand(step.command)`, run the command once directly via `deps.runner.run()`
   - If exitCode === 0: proceed normally (deduct budget, log, update context)
   - If exitCode !== 0 AND self-healing deps are available (correctionModel + skill present):
     - Build SelfHealContext from ExecutionDeps fields
     - Call `selfHealStep(step, failedResult, context)`
     - If result.status === 'success': use result.finalResult and result.commandUsed for audit/context
     - If result.status === 'exhausted' or 'budget_exceeded': rollback, log, halt with full attempt history
     - Log all correction attempts via auditLogger
   - If exitCode !== 0 AND self-healing deps are NOT available:
     - Fall back to current CircuitBreaker behavior (backwards compatible)
   - Import `selfHealStep` from `./self-healer.js`
   - Import `needsShell, runShellCommand` from `./runner.js` (already partially imported)

3. **Update RollingContext with actual command used**:
   - After self-healing success, create a modified step object with `commandUsed` replacing `step.command`
   - Pass this modified step to `context.addStepResult()` so rolling context tracks what actually ran

4. **Handle shell mode for first attempt too**:
   - Before first execution, check `needsShell(step.command)`. If true, use `runShellCommand` instead of `parseCommand + runner.run`. Import `runShellCommand` from `./runner.js`.

5. **Update executor.test.ts**:
   - Add tests for self-healing integration:
     - Test: command fails, self-healing succeeds on second try, step reports success
     - Test: command fails, no correctionModel in deps, falls back to CircuitBreaker behavior
     - Test: self-healing exhausted, executor halts with 'self_heal_exhausted' reason
     - Test: rolling context receives actual corrected command, not original
   - Mock `selfHealStep` in these tests (the unit tests for selfHealStep itself are in Plan 01)
   - Keep existing executor tests passing (they don't provide correctionModel, so they hit CircuitBreaker path)
