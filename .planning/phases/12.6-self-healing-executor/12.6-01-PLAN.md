<objective>
Build the self-healing executor module: correction prompt builder, LLM response parser, error-driven retry loop with full safety pipeline validation, post-correction effect verification, and all supporting types/config.

Purpose: This is the core new module that replaces blind CircuitBreaker retries with LLM-corrected retries. When a command fails, the self-healer captures stderr + exit code, asks the LLM for a corrected command, validates it through the full safety pipeline (allowlist + validator + rewriter), and retries. Max 3 attempts, each costing damage budget points. For WRITE-risk steps, after a corrected command succeeds (exit 0), the self-healer runs an evidence verification command to confirm the intended change actually happened (per user decision: "verify actual effect after exit 0").

Output: `src/execution/self-healer.ts` with tests, types in `types.ts`, config extension in `config/types.ts`
</objective>

    ## Self-Healer (src/execution/self-healer.ts)

    ### buildCorrectionPrompt(ctx)
    - Input: { originalCommand, stderr, exitCode, stepDescription, availableTools, containerContext }
    - Output: string prompt with template: "The following command failed... Generate a corrected command. Output ONLY the corrected command, nothing else."
    - MUST include: original command, full stderr, exit code, step description
    - MUST include: available tools from skill, container context
    - MUST NOT include: previous correction attempts (per user decision)

    ### buildEffectVerificationPrompt(ctx)
    - Input: { correctedCommand, stepDescription, containerContext }
    - Output: string prompt asking LLM to generate a READ-ONLY verification command that checks whether the intended effect of the corrected command actually happened
    - Template: "The command `X` was executed to achieve: `Y`. Generate a single READ-ONLY verification command that checks whether the intended effect actually happened. Output ONLY the verification command, nothing else."
    - The verification command must be a read operation (ls, stat, cat, id, etc.) -- never a write

    ### extractCommandFromLLMResponse(text)
    - Strip markdown code fences (```bash ... ```)
    - Take first non-empty line that looks like a command
    - Skip prose lines starting with The/This/I/You/Note/Here/To
    - Skip lines shorter than 3 chars
    - Fallback: return full cleaned text
    - Test cases:
      - "chown 1000:1000 /app/data" => "chown 1000:1000 /app/data"
      - "```bash\nchown 1000:1000 /app/data\n```" => "chown 1000:1000 /app/data"
      - "The corrected command is:\nchown 1000:1000 /app/data" => "chown 1000:1000 /app/data"
      - "  \n  chown 1000:1000 /app/data  \n  " => "chown 1000:1000 /app/data"

    ### validateCorrectedCommand(command, context)
    - Step 1: enforceSkillAllowlist(command, skill) -- if blocked, return { allowed: false, reason }
    - Step 2: validateCommand(command, safetyConfig) -- if blocked, return { allowed: false, reason }
    - Step 3: dynamicRewrite(validatedCommand, rewriteRules, containers)
    - Return: { allowed: true, command: rewrittenCommand }
    - Test: blocked command returns allowed=false with reason
    - Test: allowed command returns allowed=true with rewritten command

    ### verifyEffect(correctedCommand, context)
    - Only called for WRITE-risk or DESTRUCTIVE-risk steps (skip for READ-risk)
    - Asks LLM via generateText for a read-only verification command using buildEffectVerificationPrompt
    - Parses response via extractCommandFromLLMResponse
    - Validates verification command through safety pipeline (must be allowed, must be read-risk only via validateCommand)
    - If verification command is not read-risk or not allowed: skip verification, log warning, return { verified: true, skipped: true } (fail-open -- don't block success on bad verification command)
    - Executes verification command via runner
    - If exit code 0 and stdout is non-empty: return { verified: true, evidence: stdout }
    - If exit code != 0 or stdout empty: return { verified: false, reason: stderr || 'no output' }
    - Per user decision: "verify actual effect after exit 0 -- evidence gate: run verification command after fix"

    ### selfHealStep(step, failedResult, context)
    - Loop up to context.maxAttempts times:
      1. Check damage budget -- if can't afford, return { status: 'budget_exceeded' }
      2. Build correction prompt (fresh each time, only latest error)
      3. Call LLM via generateText with correctionTimeoutMs
      4. Parse LLM response via extractCommandFromLLMResponse
      5. Detect shell mode via needsShell() on corrected command
      6. Validate through full safety pipeline via validateCorrectedCommand
      7. If safety blocked: log audit, deduct budget, push attempt with 'blocked_by_safety', continue
      8. Execute corrected command (use runShellCommand if needsShell, else runner.run with parseCommand)
      9. Deduct budget cost
      10. If exit code 0:
          a. If step.risk is 'write' or 'destructive': call verifyEffect(correctedCommand, context)
          b. If verification returns { verified: false }: log audit 'effect_unverified', push attempt with 'effect_unverified' outcome, update failedResult with a synthetic error { stderr: "Effect verification failed: {reason}", exitCode: 1 }, continue loop
          c. If verification returns { verified: true } or step.risk is 'read': push attempt with 'success', return { status: 'success', finalResult, attempts }
      11. If failed: update failedResult to this result, push attempt with 'failed', continue
    - After all attempts: return { status: 'exhausted', attempts, commandUsed }
    - Each attempt logged via auditLogger.logExecution('self_heal_attempt', {...})
    - On exhaustion: auditLogger.logExecution('self_heal_exhausted', {...})
