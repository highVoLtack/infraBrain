    - StreamingText with text="" renders nothing visible (empty or placeholder)
    - StreamingText with text="hello world" renders "hello world"
    - StreamingText with 100+ lines of text only renders the last N lines (windowed, N=20 default)
    - DPEVPhaseHeader with {name:'discovery', model:'Qwen3-32B', status:'active', startedAt: now-5000} shows "DISCOVERY", "Qwen3-32B", and elapsed time >= 5s
    - DPEVPhaseHeader with {status:'complete'} shows checkmark icon
    - CacheHitBanner with {confidence: 0.92, sourceSessionId: 'abc', sourceDate: '2026-04-10', skillName: 'docker-postgres', provider: 'Docker'} renders confidence percentage, source info, and provider badge
  </behavior>
  <action>
1. Create `src/ui/components/StreamingText.tsx`:
   - Props: `{ text: string; maxLines?: number }` (maxLines defaults to 20)
   - Split text by newlines, take last `maxLines` lines for display
   - Render each line as `<Text>` inside a `<Box flexDirection="column">`
   - Handle empty text gracefully (render nothing)

2. Create `src/ui/components/DPEVPhaseHeader.tsx`:
   - Props: `{ phase: DPEVPhaseState }`
   - Display: `[statusIcon] PHASE_NAME -- model_name -- elapsed`
   - Use `statusIcon(phase.status)` from theme for the icon
   - Elapsed time: `Math.floor((Date.now() - phase.startedAt) / 1000)` seconds, formatted as `Xs` or `Xm Ys`
   - For active phases, use a 1-second interval (via `useEffect` + `setInterval`) to update elapsed time live
   - Phase name uppercase and bold
   - Model name dimmed
   - When status is 'complete': show completedAt - startedAt as final elapsed, stop interval

3. Create `src/ui/components/CacheHitBanner.tsx`:
   - Props: `{ confidence: number; similarity: number; sourceSessionId: string; sourceDate: string; skillName: string; provider?: string; resourceType?: string; onResponse: (useCache: boolean) => void }`
   - Render as a visually distinct callout box (Ink `<Box>` with borderStyle and borderColor='yellow')
   - Display: "CACHE HIT" header, confidence as percentage, source session ID (truncated to 8 chars), date, skill name
   - Show provider and resourceType if provided (per user decision: all displays must include provider/resourceType)
   - At bottom: "Use cached fix? [Y/n]" prompt
   - Use `useInput` to capture Y/N response, call `onResponse(true/false)`

4. Create initial `tests/ui/components.test.tsx`:
   - Import `render` from `ink-testing-library`
   - Test StreamingText: render with empty text, with short text, with 30-line text (verify windowing)
   - Test DPEVPhaseHeader: render with active phase (verify phase name, model name appear), render with complete phase (verify checkmark)
   - Test CacheHitBanner: render with props, verify confidence percentage and source session ID appear, simulate 'Y' input and verify onResponse called with true
  </action>

<task type="auto" tdd="true">
  <name>Task 2: Build StepCard, ApprovalWrite, and ApprovalDestructive components</name>
  <files>src/ui/components/StepCard.tsx, src/ui/components/ApprovalWrite.tsx, src/ui/components/ApprovalDestructive.tsx, tests/ui/components.test.tsx</files>
  <behavior>
    - StepCard with {stepIndex:0, total:3, command:'docker ps', risk:'read', status:'success'} shows "1/3", command, green risk badge, checkmark
    - StepCard with {status:'failed'} shows red cross icon and expands stdout/stderr
    - StepCard with {status:'running'} shows spinner
    - ApprovalWrite renders command and [Y/n] prompt, Y input calls onResponse(true), N input calls onResponse(false)
    - ApprovalDestructive renders command and "Type target to confirm:" prompt, correct target input calls onResponse(true), wrong input shows error
  </behavior>
  <action>
1. Create `src/ui/components/StepCard.tsx`:
   - Props: `{ step: StepState; isActive?: boolean }`
   - Layout: horizontal Box showing `[step N/total] [statusIcon] command [riskBadge]`
   - Step number: `stepIndex + 1` / total
   - Status icon from theme: pending=dot, running=spinner (@inkjs/ui Spinner if available, else rotating char), success=checkmark, failed=cross, skipped=dash
   - Risk badge: colored text `[risk]` using `riskColor(step.risk)` from theme
   - Show provider and target if available: `on {target}` suffix
   - Output area: hidden by default. Auto-expand (show stdout/stderr in dimmed text) when status is 'failed' or when `isActive` is true
   - Output text truncated to last 10 lines to prevent overflow

2. Create `src/ui/components/ApprovalWrite.tsx`:
   - Props: `{ command: string; riskLevel: string; onResponse: (approved: boolean) => void }`
   - Render command in yellow (WRITE risk color)
   - Prompt: `Execute "command"? [Y/n]`
   - Use Ink's `useInput` hook (NOT readline):
     - 'y', 'Y', or Enter -> onResponse(true)
     - 'n', 'N' -> onResponse(false)
   - After response: show "Approved" (green) or "Rejected" (red) and disable further input (set responded=true state)
   - Per user decision: three tiers preserved, this handles WRITE tier

3. Create `src/ui/components/ApprovalDestructive.tsx`:
   - Props: `{ command: string; target: string; onResponse: (approved: boolean) => void }`
   - Render command in red (DESTRUCTIVE risk color) with bold warning
   - Prompt: `DESTRUCTIVE: "command" -- Type "target" to confirm:`
   - Use @inkjs/ui `TextInput` component (if available) or Ink's `useInput` to capture character-by-character input building a confirmation string
   - On Enter: compare typed string to target. Match -> onResponse(true). Mismatch -> show "Target mismatch" error in red, allow retry
   - After successful confirmation: show "Confirmed" and disable further input
   - Per user decision: this handles DESTRUCTIVE tier

4. Add tests to `tests/ui/components.test.tsx`:
   - StepCard tests: render with success status (verify checkmark and command text), render with failed status (verify stderr shown), render with different risk levels (verify correct color word in output)
   - ApprovalWrite tests: render and simulate 'Y' keystroke via `stdin.write('Y')`, verify onResponse called with true. Render and simulate 'N', verify onResponse called with false.
   - ApprovalDestructive tests: render with target 'nginx', simulate typing 'nginx' + Enter, verify onResponse called with true. Simulate typing 'wrong' + Enter, verify error message appears and onResponse not yet called.
  </action>
