  <name>Task 1: Implement useDPEV state machine reducer</name>
  <files>src/ui/hooks/useDPEV.ts, tests/ui/dpev-panel.test.tsx</files>
  <behavior>
    - dpevReducer with PHASE_START action adds new phase to phases array and sets activePhaseIndex
    - dpevReducer with TOKEN action appends text to active phase's tokens string
    - dpevReducer with PHASE_COMPLETE action sets active phase status to 'complete' and sets completedAt
    - dpevReducer with CACHE_HIT action sets cacheHit and status to 'awaiting-approval'
    - dpevReducer with APPROVAL_REQUIRED action sets pendingApproval and status to 'awaiting-approval'
    - dpevReducer with APPROVAL_RESPONSE clears pendingApproval and resumes
    - dpevReducer with STEP_UPDATE action updates executionSteps array at given index
    - dpevReducer with COMPLETE action sets status to 'complete'
    - dpevReducer with ERROR action sets status to 'error'
    - useDPEV hook wires SSE events to dispatch: dpev:phase -> PHASE_START/PHASE_COMPLETE, dpev:token -> TOKEN, etc.
  </behavior>
  <action>
1. Create `src/ui/hooks/useDPEV.ts`:
   - Export `dpevReducer(state: DPEVState, action: DPEVAction): DPEVState` as a pure function (testable without React).
   - Reducer logic:
     - `PHASE_START`: Push new DPEVPhaseState to phases array with status 'active', set activePhaseIndex to new index, set overall status to 'streaming'
     - `TOKEN`: Append text to `phases[activePhaseIndex].tokens`. If no active phase, no-op.
     - `PHASE_COMPLETE`: Find phase by name in phases array, set status='complete', completedAt=Date.now()
     - `CACHE_HIT`: Set cacheHit provenance, set status='awaiting-approval'
     - `PLAN_READY`: Set fixPlan
     - `STEP_UPDATE`: Update or push into executionSteps at stepIndex, set status to 'executing' if overall status wasn't already
     - `APPROVAL_REQUIRED`: Set pendingApproval, set status='awaiting-approval'
     - `APPROVAL_RESPONSE`: Clear pendingApproval, set status back to 'executing' (or 'streaming' if during DPEV)
     - `COMPLETE`: Set status='complete'
     - `ERROR`: Set status='error', optionally store error message

   - Export `useDPEV(apiBaseUrl: string, prompt: string)` hook:
     - Uses `useReducer(dpevReducer, initialState)` where initialState has empty phases, status='idle'
     - Uses `useSSE` to connect to `${apiBaseUrl}/stream/debug` with POST body `{ prompt }`
     - Maps SSE events to dispatch calls:
       - `dpev:phase` with status='active' -> dispatch PHASE_START
       - `dpev:phase` with status='complete' -> dispatch PHASE_COMPLETE
       - `dpev:token` -> dispatch TOKEN
       - `dpev:cache-hit` -> dispatch CACHE_HIT
       - `dpev:plan` -> dispatch PLAN_READY
       - `exec:step` -> dispatch STEP_UPDATE
       - `exec:approval` -> dispatch APPROVAL_REQUIRED
       - `dpev:complete` -> dispatch COMPLETE
       - `dpev:error` -> dispatch ERROR
     - Returns `{ state: DPEVState; dispatch: Dispatch<DPEVAction> }`

   - Test PHASE_START adds phase and updates activePhaseIndex

   - Test STEP_UPDATE adds/updates execution steps
   - Test APPROVAL_REQUIRED -> APPROVAL_RESPONSE cycle
   - Test COMPLETE sets final status
   - Test ERROR sets error status

1. Create `src/ui/panels/DPEVPanel.tsx`:
   - Props: `{ apiBaseUrl: string; prompt?: string; replaySession?: DPEVState }` (replaySession for read-only past session view)
   - If `prompt` is provided: use `useDPEV(apiBaseUrl, prompt)` to get live state
   - If `replaySession` is provided: use that state directly (read-only, no SSE connection)
   - If neither: render idle state "No active session"
   - Layout: `<Box flexDirection="column" flexGrow={1}>`
   - For each phase in `state.phases`:
     - If phase.status === 'complete': render collapsed 1-line summary:
       `<DPEVPhaseHeader phase={phase} />` showing "DISCOVERY [checkmark] 1.2s -- 3 containers found" style
     - If phase.status === 'active': render expanded:
       `<DPEVPhaseHeader phase={phase} />` (with live timer)
       `<StreamingText text={phase.tokens} />` (token-by-token streaming)
     - If phase.status === 'error': render with error styling
   - Cache hit interruption: if `state.cacheHit` is set and status is 'awaiting-approval' AND no `state.pendingApproval` (distinguishes cache hit from execution approval):
     - Render `<CacheHitBanner ...provenance onResponse={handleCacheResponse} />` INLINE, replacing the diagnosis phase area
     - `handleCacheResponse(useCache: boolean)`:
       - POST to `${apiBaseUrl}/stream/debug/approve` with body `{ sessionId: state.sessionId, useCache }` (the dedicated cache hit approval endpoint created in Plan 02 Task 1)
       - On success: dispatch APPROVAL_RESPONSE. If useCache=true, pipeline continues with cached fix. If useCache=false, pipeline re-diagnoses (server-side handling via requestCacheApproval resolver).
       - On fetch error: show error text, allow retry
   - Execution phase: when `state.executionSteps.length > 0`:
     - Render all steps as `<StepCard step={step} />` simultaneously (per user decision: show all steps at once)
     - If `state.pendingApproval` is set:
       - For WRITE risk: render `<ApprovalWrite>` inline within the step card area
       - For DESTRUCTIVE risk: render `<ApprovalDestructive>` inline
       - On response: POST to `${apiBaseUrl}/stream/execute/approve` with `{ stepIndex: state.pendingApproval.stepIndex, approved }` (the execution step approval endpoint created in Plan 02 Task 2). On success: dispatch APPROVAL_RESPONSE.
   - Completion: when status='complete', show a summary footer
