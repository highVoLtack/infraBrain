    - POST /stream/debug with {prompt} returns Content-Type: text/event-stream

    - Stream emits dpev:cache-hit event when cache fast-path detected; pipeline pauses until approval
    - Stream emits dpev:diagnosis event with structured diagnosis on completion
    - Stream emits dpev:plan event with fix plan on planning completion
    - Stream emits dpev:complete event when pipeline finishes
    - Stream emits dpev:error on pipeline failure
    - Missing prompt returns 400 JSON (not SSE)
    - POST /stream/debug/approve with {useCache: true} resolves cache hit pause and continues with cached fix
    - POST /stream/debug/approve with {useCache: false} resolves cache hit pause and re-runs diagnosis from scratch (noCache: true)
    - POST /stream/debug/approve with no pending cache hit returns 404
  </behavior>
  <action>
1. Create `src/api/routes/stream-debug.ts`:
   - Export `createStreamDebugRoute(deps)` function matching the existing route factory pattern (same deps as createDebugRoute plus provider, config, sessionId).
   - `initSSE(res)` helper: sets headers `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`, calls `res.flushHeaders()`.
   - `sendEvent(res, event, data)` helper: writes `event: ${event}\ndata: ${JSON.stringify(data)}\n\n`.
   - Use a per-request `cacheHitResolver` variable: `{ resolve: (useCache: boolean) => void } | null` to store the pending cache hit approval Promise resolver. This is scoped to the active SSE session.
   - POST `/` handler (SSE streaming DPEV):
     a. Validate prompt (return 400 JSON if missing -- NOT SSE, since client can't parse SSE error before connection)
     b. Call `initSSE(res)`
     c. Create an `onEvent` callback that calls `sendEvent(res, event, data)` for each pipeline event
     d. Create a `requestCacheApproval` callback: when called with cache hit provenance, it sends `dpev:cache-hit` SSE event, then returns a Promise that resolves when the user responds via POST /stream/debug/approve. Store the Promise resolver in `cacheHitResolver`.
     e. Call `runDPEV(input)` with onEvent AND requestCacheApproval injected
     f. On completion, send `dpev:complete` event, then `res.end()`
     g. On error, send `dpev:error` event, then `res.end()`
   - POST `/approve` handler (cache hit approval -- regular JSON endpoint, NOT SSE):
     a. Accept `{ useCache: boolean }`
     b. Look up the `cacheHitResolver` for the active session
     c. Resolve the Promise with the useCache boolean
     d. Clear `cacheHitResolver`
     e. Return 200 JSON `{ ok: true }`
     f. If no pending cache hit (cacheHitResolver is null), return 404 JSON `{ error: 'No pending cache hit approval' }`
   - IMPORTANT: The resolver map must be shared between the POST `/` and POST `/approve` handlers. Use a module-scoped Map keyed by sessionId so concurrent sessions don't collide: `const cacheApprovals = new Map<string, { resolve: (useCache: boolean) => void }>()`. The POST `/` handler generates a sessionId (or uses the one from DPEVInput), stores the resolver. The POST `/approve` handler accepts `{ sessionId, useCache }` and looks up by sessionId.
   - Handle client disconnect: `req.on('close')` -- if cacheHitResolver is pending, resolve with false (reject cache, abort). Remove from map.
