  <action>
Create demo/permission-trap/ directory structure following the Chaos Library pattern.

**docker-compose.yml:**
- Single service `permission-app`
- `build: ./app`
- `container_name: permission-app`
- No ports needed (app doesn't serve anything)
- No volumes needed (everything is inside the container)

**app/Dockerfile:**
```dockerfile
FROM python:3-slim
WORKDIR /app
# Create data directory as root with restrictive permissions
RUN mkdir -p /app/data && \
    chown root:root /app/data && \
    chmod 700 /app/data
COPY app.py /app/app.py
# Switch to non-root user UID 1000
USER 1000
CMD ["python", "/app/app.py"]
```

Key: The RUN instruction executes as root (default before USER), creating /app/data owned by root:root with mode 700 (rwx------). USER 1000 switches to non-root for CMD. When app.py tries to write to /app/data/status.pid, it gets PermissionError.

**app/app.py:**
Per RESEARCH.md recommendation, the app stays alive after the error (sleep loop) so `docker exec` works for diagnostics. This matches the pattern from docker-storage (logger stays alive).

```python
import os
import sys
import time

pid_path = "/app/data/status.pid"
print(f"Writing PID to {pid_path}...")

try:
    with open(pid_path, "w") as f:
        f.write(str(os.getpid()))
    print(f"PID {os.getpid()} written successfully.")
except PermissionError as e:
    print(f"FATAL: Permission denied writing to {pid_path}: {e}", file=sys.stderr)
    # Don't exit -- stay alive for diagnostics (docker exec)
    print("Entering idle loop for diagnostic access...", file=sys.stderr)
    while True:
        time.sleep(60)
```

The broken state is: container running but app failed to write PID file + logs show "Permission denied". The success state (after fix) is: logs show "PID written successfully".

<task type="auto">
  <name>Task 2: Create idempotent reset script with broken-state verification</name>
  <files>demo/permission-trap/reset-permission-trap.sh</files>
  <action>
Create `demo/permission-trap/reset-permission-trap.sh` following the reset-docker-storage.sh template.

**Script flow:**
1. `set -euo pipefail`
2. Resolve SCRIPT_DIR and COMPOSE_FILE from script location
3. Tear down: `docker compose -f "$COMPOSE_FILE" down --remove-orphans 2>/dev/null || true`
4. Start: `docker compose -f "$COMPOSE_FILE" up -d --build`
5. Poll loop (max 30s, checking every 2s = 15 iterations):
   - Check container is running: `docker inspect --format '{{.State.Status}}' permission-app` = "running"
   - Check logs for Permission Denied: `docker logs permission-app 2>&1 | grep -q "Permission denied"`
   - BOTH conditions must be true: container running AND logs show Permission Denied
6. On success: print "SUCCESS: permission-app running with Permission Denied error" and exit 0
7. On timeout: print error and exit 1

Make script executable: `chmod +x`

**Key differences from docker-storage reset:**
- Checks for container "running" state (not "exited") because the app stays alive via sleep loop
- Uses `docker logs ... | grep` for error verification instead of application-level health check
- Shorter timeout (30s) since the Permission Denied error occurs immediately on container start
- Single container check (not dual like logger + Redis)
