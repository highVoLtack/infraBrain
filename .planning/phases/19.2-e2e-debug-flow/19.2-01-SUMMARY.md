## Decisions Made

- **Single SSE connection for execution:** Kept execution inside `/stream/debug` (research recommendation) rather than opening a second SSE to `/stream/execute`. This avoids race conditions in the Ink client's `useSSE` hook and simplifies lifecycle management.
- **Verification as simple heuristic:** Instead of LLM-based verification, re-run the same discovery commands the pipeline used and emit `dpev:verification { passed, discoveryOutput }` where `passed = (executionResult.status === 'completed')`. UI can decide how to render fresh discovery output. Keeps Phase 19.2 scope tight.
- **Plan rejection ends cleanly:** User Ns the plan -> session status `completed` (not `rejected`), `dpev:complete { status: 'plan_rejected' }`. Allows user to re-run with different prompt.
- **Auto-approve read steps:** The `requestApproval` callback in the executor auto-returns `{ approved: true }` for risk=='read' steps. Write/destructive steps emit `exec:approval` and wait on the `stepApprovals` map.
- **`DPEVResult.discoveryCommands` (optional):** Added so stream-debug route can re-run discovery during verification without re-parsing the skill. Safe default when skill has no discovery (empty array omitted).
