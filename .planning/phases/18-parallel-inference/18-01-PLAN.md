    **inference-types.ts**: Create types file with:
    ```typescript
    export type InferenceMode = 'parallel' | 'sequential';

    export interface BackendStatus {
      baseUrl: string;
      available: boolean;
      models: string[];
      responseTimeMs: number;
    }

    export interface InferenceTask<T> {
      label: string;           // For timing logs: "9B-noise-filter", "122B-diagnosis"
      role: ModelRole;         // Maps to registry.get(role) for backend resolution
      execute: () => Promise<T>;
    }

    export interface InferenceResult<T> {
      label: string;
      status: 'fulfilled' | 'rejected';
      value?: T;
      reason?: string;
      startMs: number;
      endMs: number;
      durationMs: number;
    }

    export interface SchedulerConfig {
      probeTTLMs: number;      // How long to cache probe results (default: 30000)
      probeTimeoutMs: number;  // Per-backend probe timeout (default: 3000)
    }
    ```

    **inference-scheduler.ts**: Create scheduler with:
    1. `createInferenceScheduler(config: InfraBrainConfig, registry: ModelRegistry, opts?: Partial<SchedulerConfig>)` factory
    2. Internal state: `cachedProbe: { results: BackendStatus[], timestamp: number } | null`
    3. `probeBackends()`: Use `extractUniqueBackendUrls(config)` to get URLs, then `Promise.all` with fetch to `/models` endpoint (same pattern as health.ts). Cache results with TTL. Return if cache is fresh.
    4. `isAvailable(role: ModelRole)`: Look up the role's baseUrl from config.modelMap, check if that URL is in cached probe results as available.
    5. `getMode()`: Count distinct available baseUrls. If 2+ distinct URLs are available, return 'parallel'. Otherwise 'sequential'.
    6. `runParallel<T>(tasks: InferenceTask<T>[])`: Wrap each task.execute() in a timing wrapper that records startMs/endMs. Use `Promise.allSettled()`. Map results to InferenceResult<T>[]. Log timing in DEV_MODE using the pattern:
       ```
       [INFERENCE] Mode: parallel
       [INFERENCE] 9B-noise-filter started at +0ms
       [INFERENCE] 122B-diagnosis started at +2ms
       [INFERENCE] 9B-noise-filter completed at +150ms (150ms)
       [INFERENCE] 122B-diagnosis completed at +5200ms (5198ms)
       [INFERENCE] Overlap: 148ms
       [INFERENCE] Total: 5200ms (sequential would be: 5348ms)
       ```

    Key design decisions:
    - InferenceScheduler is a plain object (not a class) returned by factory -- matches createModelRegistry pattern
    - Backend probe reuses `extractUniqueBackendUrls` from health.ts (don't hand-roll URL extraction)
    - Probe timeout matches health.ts (3000ms default via AbortController)
    - Probe cache uses simple timestamp comparison, not interval
    - The scheduler does NOT own the model calls -- it wraps arbitrary `() => Promise<T>` functions
    - Export the InferenceScheduler interface for DPEVInput extension in Plan 02

    **Tests**: Write tests FIRST (RED), then implement (GREEN). Test file mocks `globalThis.fetch` for backend probes (same pattern as health.test.ts). Use `vi.useFakeTimers()` for TTL testing.
